# 资产库与编译链路总纲

状态：2026-10-31 草案（待评审）。范围：资产库、工程捕获、编译输入、hltools 协作。
本文取代此前分散在 `native-project-usage.md` / `native-project-format-design.md` /
`project-workspace-acceptance.md` 里关于"库与工程同步"的部分；历史设计仍可查阅，但以本文为准。

## 1. 目标

1. 一个 TB 实例只管理**一个全局资产库**，在欢迎页统一导入、转换、浏览。
2. 导入必须经过 TB：库文件夹是 TB 的私人仓库，不靠用户手工丢文件。
3. 工程**自包含**：用到的资源在捕获时嵌入 `.tbproj`，库删了/搬了都能打开和编译。
4. 编译输入就是工程文件本身：hltools 只读解析 `.tbproj` + 指定地图，不再经过 WAD 或快照目录。
5. 引擎兼容格式（GoldSrc miptex）在**导入库时**生成；WAD 不再是必需中间产物。

非目标：多用户/团队共享库、库迁移重定位、库修订历史、Q1/Q2 等其他引擎的纹理格式。

## 2. 数据模型

### 2.1 资产库

- 一个普通文件夹，索引为 `.tbassets`（SQLite，`application_id=0x54424153`），全局唯一，路径存在应用偏好里。
- 每个资源保存：**原图字节 + 转换结果（miptex 等价：256 色 + 4 级 mip）+ 元数据**（显示名、纹理名、透明/转换参数、内容哈希、更新时间）。
- **没有修订历史**：重新导入即覆盖当前内容，哈希变化用于"库里更新了"的角标提示。
- 文件夹组织：`textures/`、`models/`、`sprites/`、`sound/`、`gfx/env/`，保留原文件名。
- 未登记进索引的文件不参与浏览；库视图可提示"发现 N 个未导入文件"，但不自动吸收。

### 2.2 工程

- 捕获即嵌入：`original` + `compatible` + `conversionRecipe` + 发布名，沿用现有 `AssetImport` 结构。
- 只保留来源信息用于角标：库 ID、捕获时的内容哈希；不再存库修订号。
- 地图仍按**名字**引用纹理/模型，捕获与替换沿用资源 ID，保证引用不断。

### 2.3 贴图

- 终态是 miptex；WAD 只是历史上的一种容器，编译时不再生成。
- 编辑器默认显示**转换后效果**，需要时可查看原图。

## 3. 流程

1. **导入**（欢迎页库管理器）：选文件 → 识别类型 → 规范化纹理名（默认大写、非法字符替换、截断 15 字符，可手改）→ 冲突时询问「覆盖 / 保留两者（自动加后缀）」→ 转换 → 写入库。
2. **浏览**：内容浏览器 `Asset Library` 来源直接读全局库；预览即转换后效果。
3. **捕获**：拖入地图或 Add to Project，把选定内容嵌入工程；天空盒按六面组、模型带 `T.mdl` 与动画组依赖。
4. **更新提示**：库里同 ID 资源内容变了，工程里对应资源显示角标；点按后覆盖工程里的副本（保持 ID 与名字），不做自动同步。
5. **编译**：TB 编译对话框先保存工程，再调用
   `hltools compile --project <abs.tbproj> --map <name> [其他参数]`；
   hltools 只读打开工程（WAL），按名字解析纹理并嵌入 BSP，不产出 WAD。

## 4. 契约

### 4.1 工程文件（跨仓库只读契约）

- SQLite，`application_id=0x5442504a`，当前 `user_version=3`。
- hltools 只读打开，必须校验 application_id / user_version，版本过高时明确报错而不是猜测。
- 读取范围：地图内容、资源（原图/兼容内容/发布名/依赖）、工程信息（游戏目标）。
- 契约写进两边的测试：黄金工程样本 + 期望编译结果。

### 4.2 转换

- 以 TB 的 `TbImgLib` GoldSrc 编码器为唯一实现；hltools 只消费已转换的 miptex 字节，不再量化。
- 参数（256 色、四级 mip、≤512 且 16 倍数、`{` 前缀二值透明、alpha 阈值 128）集中记录，导入预览里可见。

### 4.3 hltools 集成方式

- 保持**独立进程**，不做进程内嵌。TB 负责构造参数、收集日志、展示进度。
- hltools 的命令行扩展由 hltools 仓库实现；TB 只依赖其公开 CLI。

## 5. 变更清单

**删除**
- 工程窗口 `Library → Attach Asset Library… / Relink Moved Library…`。
- 工程级「检查库更新 / 忽略版本」对话框与 `ProjectLibraryDialog`。
- 库修订历史与 `revision` 相关字段/流程。
- 独立 `AssetLibraryWindow`（并入欢迎页库管理器）。
- 编译快照目录作为内部通路（可保留为"导出给外部工具"的可选功能）。

**改造**
- 库导入 → 必须经 TB，导入即转换。
- 内容浏览器：`Asset Library` 来源直连全局库；`Project` 来源显示已捕获资源 + 更新角标。
- 工程存储：`LibraryLink` 去掉修订号，保留库 ID + 捕获哈希。
- 编译对话框：传 `--project`/`--map`，编译前自动保存。

**新增**
- 欢迎页库管理器（路径、导入、冲突处理、批量转换进度、库内重命名）。
- 应用偏好：全局库路径。
- 更新角标 + 点按更新。

## 6. 分阶段

- **A 库**：全局库偏好、欢迎页管理器、TB 内导入 + 导入时转换、预览转换效果、库视图。
- **B 工程**：捕获改用新库、更新角标、移除工程级库菜单与更新对话框、迁移旧工程（丢弃库关联、保留快照）。
- **C 编译**：hltools 读 `.tbproj`，TB 编译对话框切换参数；保留传统 MAP + WAD 路径。
- **D 清理**：删除修订历史、快照内部通路、独立库窗口；补验收。

## 7. 未决与风险

- 外部直接改动库文件夹：按"必须经 TB 导入"处理为未登记文件，仅提示。
- 纹理改名/重名：改名需要同步重写地图引用（参考现有 `renamePublishPath` 的做法），首版可限制为"改名仅影响未使用资源"。
- 批量导入/转换的性能与取消；大库首次索引。
- 旧工程迁移后的可读性与回滚。
- hltools 读取工程时的并发与只读保证（WAL）。
- 编译只读磁盘内容，已定编译前自动保存。

## 8. 验收要点

- 同一张 png 导入 → 库内转换结果与 hltools 嵌入 BSP 的字节一致。
- 捕获 → 删除库目录 → 重新打开工程 → 编译成功且贴图正确。
- 覆盖导入 → 工程出现角标 → 点按更新 → 地图引用与撤销链正常。
- 旧工程打开后不再显示库关联，资源与编译不受影响。
