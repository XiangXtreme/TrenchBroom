# 内置 hltools 场景教程

这是一个 Half-Life / GoldSrc 教学工程。打开同目录的 **`hltools-tutorial.tbproj`**，
在工程内容中双击地图，即可编辑六张示例地图。地图和使用的纹理都保存在工程文件里；
打开和使用内置 hltools 编译不需要另外安装 WAD 或外部编译器。建议先复制工程再练习，
以便随时回到原始对照组。

## 开始使用

1. 使用支持工程文件及内置 hltools 的本分支 TrenchBroom 打开 `.tbproj`，
   在工程内容或内容浏览器中双击 `01 光照预览与编译`。游戏配置为 **Half-Life**，
   地图格式为 **Valve**。
2. 在 3D 视口左上方点击灯泡开启光照预览，通过旁边的箭头选择质量、立即烘焙、
   自动更新或查看日志。移动灯光、修改颜色或几何体后，可以重新比较。
3. 要生成游戏用的 BSP，在地图打开时选择 **Run → Compile Map…**，点击
   **内置 hltools** 创建编译配置，选择输出路径和质量后开始编译。默认输出和日志
   位于工程旁的 `compiled` 文件夹。可以展开 **编译选项**，也可以直接填写
   **附加参数**；两处会同步。
4. 工程内提供地图和纹理，游戏运行环境仍需自行安装和配置。编译成功后，可把 BSP
   放到对应 GoldSrc 游戏的 `maps` 目录，在游戏中检查最终光照与碰撞。

预览和编译是两个独立操作。预览的“标准”为了交互速度使用快速 VIS 和正常反弹；
编译任务的“标准”使用完整 VIS。它们的默认行为如下，附加参数可以改变结果：

| 质量 | 视口光照预览 | 内置编译任务 |
| --- | --- | --- |
| 快速 | `-fast`：快速 VIS，不计算反弹 | `-fast`：快速 VIS，不计算反弹 |
| 标准 | `-previewfastvis`：快速 VIS，默认 8 次反弹 | 默认完整 VIS、8 次反弹 |
| 最高/精细 | `-extra`：完整 VIS，默认 12 次反弹和额外采样 | `-extra`：完整 VIS，默认 12 次反弹和额外采样 |

这里的“默认 8/12 次”是未另设 `-bounce` 时的值；`-fast` 会关闭反弹。
首次烘焙和修改几何体可能较慢；只调整灯光时，预览可以复用已缓存的几何数据。

## 01 · 光照、反弹和软阴影

地图 `01_lighting` 有冷暖两组灯光、一面蓝色挡板、柱体、地面交界和一个使用
`info_texlights` 的发光纹理面。先在视口中比较快速、标准和最高预览，重点看挡板背面、
柱脚和阴影边缘。发光纹理由 `info_texlights` 中的 `LAMP` 属性控制。

想比较附加参数时，请用内置编译任务的**标准**质量，并分别修改参数、重新编译；
最终效果在编译出的 BSP 中比较。视口预览质量菜单不会读取这里的附加参数。

| 对比 | 附加参数 | 观察重点 |
| --- | --- | --- |
| 反弹 | `-bounce 0` 与 `-bounce 8` | 灯光背面与挡板另一侧的间接光 |
| 环境遮蔽 | 无参数与 `-ao -aoscale 64 -aostats` | 柱脚、墙角的接触阴影；日志中的 AO 统计 |
| PCF | 无参数与 `-pcf 2` | 挡板投影边缘，采样增多也会增加耗时 |
| 模糊约束 | 无参数与 `-blurclamp 0.75` | 明暗边缘的混合结果 |

AO、`-pcf` 大于 1 或 `-lightcull` 与 GPU 一起启用时，直接光采集会回退到 CPU；
可以从编译日志确认实际路径。`-blurclamp` 本身不要求 CPU 回退。先单独比较参数，
再组合使用更容易看懂它们各自的作用。

## 02 · func_detail：层级、切割和共面

地图 `02_detail_csg` 是四组并排实验。每组有两排形状相同的蓝色基体和橙色相交体：
A 排中心 `y=-144`，B 排中心 `y=144`。沿 X 方向依次是四个实验。选中物体后，
在实体属性里通过 `targetname` 和 `zhlt_…` 字段核对数值；名称例如 `02_b_cutter`。

| 组 / X 中心 | A 排 | B 排 | 练习 |
| --- | --- | --- | --- |
| 01 / -800 | 两者 `detaillevel=1` | 橙色体 `detaillevel=2` | 比较不同层级的相交画刷 |
| 02 / -256 | 橙色体层级 2，`chopdown=0` | 橙色体层级 2，`chopdown=1` | 橙色体降低有效切割层级 |
| 03 / 256 | 蓝色体 `chopup=0` | 蓝色体 `chopup=1` | 蓝色体提高被切割时的有效层级 |
| 04 / 800 | 蓝色 `coplanarpriority=1` | 橙色 `coplanarpriority=1` | 比较两种纹理在重叠共面区域的取舍 |

这些参数作用于编译后的面和碰撞树，源地图的两个画刷在编辑器里仍然相交，
并非每组都会直接改变表面外观。建议每次只改一个字段并重新编译。要保留 CSG 中间
结果，在附加参数中填写 `-dumpintermediates`；编译输出旁会有 `.p0` 等文件，可用
文本差异工具或 BSP 检查工具比较。共面优先级还可在游戏或 BSP 查看器中检查重叠处
最终保留的纹理。

`zhlt_detaillevel` 控制细节层级；普通细节通常从 1 开始。当前实现判断可否切割时，
比较 `切割体层级 - chopdown` 与 `被切割体层级 + chopup`。`coplanarpriority` 在
相同细节层级的共面重叠面中决定优先顺序。`func_detail` 不能代替封闭地图的世界墙体。

## 03 · func_detail：碰撞

地图 `03_detail_collision` 的前四组是相同的阶梯，分别设置了 `zhlt_cliptype`：

| X 中心 | 名称 | 设置 |
| --- | --- | --- |
| -800 | `01_simple` | `simple` |
| -480 | `02_legacy` | `legacy` |
| -160 | `03_legacytrim` | `legacytrim` |
| 160 | `04_normalized` | `normalized` |

在 Play 模式和目标游戏中沿阶梯及接缝行走，结合编译日志的 hull / clipnode 统计
比较。不同形状才可能显现不同结果；简单台阶不保证每种模式都有明显的手感差异。
`legacytrim` 是本分支提供的连续外表面碰撞模式，应在实际目标游戏中检查接缝。

另外两组是成对实验：

- X=480：A 排 `05_a_solid` 与 B 排 `05_b_noclip` 外形相同，后者设置
  `zhlt_noclip=1`。尝试穿过它们，比较可见几何和玩家碰撞。
- X=800：两排都是相交的蓝、橙画刷。A 排两个画刷的 `zhlt_clipnodedetaillevel`
  都是 1；B 排蓝色基体为 0、橙色体为 1。比较编译数据和日志；该属性控制碰撞树
  的细节层级，不是把画刷设为可穿透的开关。

预览烘焙内部使用 `-noclip` 加速，不生成游戏用的碰撞 hull；不要据此判断最终 BSP
的碰撞。游戏发布用编译配置也不要为了加速而随意加入 `-noclip`。

## 04 · HINT、SKIP 和其他工具纹理

地图 `04_tools_hint` 有两个错开的门洞，便于观察 BSP 分割。第一个门洞
`x=-176` 处有一片很薄的工具画刷：一个面为 **HINT**，另外五个面为 **SKIP**。

1. 使用内置 hltools 编译，在附加参数中填写 `-dumpintermediates`。
2. 在地图窗口选择 **File → Load Portal File…**，打开输出旁的
   `04_tools_hint.prt`。门户会以半透明多边形显示。
3. 复制这份 `.prt` 留作对照；回到源地图，把薄画刷上的 HINT 面改为 SKIP，重新编译，
   再加载新 `.prt`。比较门洞附近的门户。两次请使用相同编译质量和参数。

HINT 用于提示 BSP 选择分割平面，SKIP 用于舍弃不需要的工具面；它们不是用来封闭地图
的实体墙。门户文件展示几何分割，并不直接展示每个叶区的最终 PVS；并非增加 HINT
就一定能让 VIS 更快，应结合具体场景测量。

右侧区域还有这些例子：

| 纹理 | 教学位置 | 作用 |
| --- | --- | --- |
| `CLIP` | `x=480..496, y=-96..96` 的薄画刷 | 不绘制的碰撞阻挡，适合简化玩家移动边界 |
| `NULL` | `x=384..448, y=160..224` 方柱的底面 | 不需要绘制的面；不要随意放在玩家能看到的表面 |
| `NOCLIP` | `x=512..576, y=160..224` 橙柱的底面 | 本编译器把该面按 NULL 处理，并关闭整个画刷的碰撞 |

工具纹理在编辑器中的可见方式与最终 BSP 不同。请结合 Play、编译结果及目标游戏检查，
尤其不要用 CLIP、HINT 或 SKIP 来代替封闭世界的实体墙。

## 05 · info_portal 和 PVS

地图 `05_info_portal` 的两间房间由实墙隔开，方便清楚地观察 PVS 差异；它们不是
推荐用于优化普通墙体的固定模板。左房的 `info_portal` 位于 `(-480, 0, 64)`，
目标 `portal_east` 位于 `(480, 0, 64)`，默认 `oneway=0`，两边的邻接范围均为 0。
链接只改变潜在可见性集合，不会在实墙上开洞，也不等于该位置有实际视线。

按标准质量编译后，在本教程文件夹打开 PowerShell，运行：

```powershell
python .\inspect_pvs.py .\compiled\05_info_portal.bsp --from -480 0 64 --to 480 0 64
```

如果工程副本放在其他位置，把 BSP 路径改为那个工程旁的 `compiled` 文件夹。脚本
需要 Python 3，读取 GoldSrc BSP v30 的世界叶区及压缩 VIS 数据；无需安装额外库。

| 操作后重新编译 | A → B | B → A |
| --- | --- | --- |
| 保持默认双向链接 | visible | visible |
| 将 `oneway` 改为 `1` | visible | not visible |
| 删除或断开 `info_portal` | not visible | not visible |

`neighbor`、`targetneighbor` 控制向相邻门户扩展的层数；目标可用分号分隔多个名称。
`reverse=1` 用于移除指定的可见关系，应谨慎使用并验证游戏内是否出现物体消失。
本示例设置了明确的 `oneway` 值；旧式单个 `info_leaf` 链接若没有新选项，仍保留
原有的单向默认行为。

## 06 · 漏空排查

地图 `06_leak` **故意缺少东侧墙体**。编译应报告 `LEAK` 并停止；这是练习结果。
在输出旁找到 `06_leak.pts`，通过 **File → Load Point File…** 加载，沿着点线找到
室内连接到虚空的位置。用普通世界画刷补上东墙：`x=304..320`、`y=-256..256`、
`z=0..256`，重新编译直至不再报漏空。不要用 `func_detail` 或工具纹理补洞。

## 维护与验证

本教程的纹理由 `generate_textures.py` 原创生成，并以 WAD3 内嵌；没有使用第三方游戏
纹理。`tutorial-textures.wad` 是重建工程用的源文件，日常打开 `.tbproj` 无需它。
修改生成脚本或源 WAD 后，可在仓库根目录运行：

```powershell
python examples/hltools-tutorial/generate.py
python examples/hltools-tutorial/verify.py --worker build-release-codex/app/TrenchBroom/HltoolsLightmapWorker.exe
```

验证脚本会编译五张正常地图并确认漏空地图失败，还会检查光照、细节参数、碰撞、
HINT 和 `info_portal` 的实际差异。纹理重建需 Python、Pillow 和
`goldsrc-map-assets` 的 `texture-audit`、`wad-build`、`wad-inspect` 工具。
