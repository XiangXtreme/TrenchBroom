# TB 工程试用说明

当前实现包含 `.tbproj` 工程、独立资产库、工程资源快照与编译快照导出。传统独立
MAP 编辑仍可使用。

## 创建与打开

1. 在欢迎页选择 **New Project…**，或在地图窗口选择 **File → New Project…**。
2. 选择游戏及地图格式，保存 `.tbproj`。首验目标为 Counter-Strike 1.6 对应的游戏配置。
3. 工程窗口管理内容与版本，地图在窗口内的标签中编辑；切换标签保留各自的编辑状态。
4. **Project → New Map…** 创建其他地图；**Import Files…** 导入已有内容。
5. 双击工程内容列表或 Asset Browser 中的地图，打开或切换其编辑标签。
   原有打开文件入口也支持 `.tbproj`。

## 资产库

资产库是一个普通文件夹，内含隐藏目录文件 `.tbassets`。库不是工程，可以同时被
多个工程引用，也可以整体移动。

1. 建立一个文件夹，把 WAD、PNG/BMP/TGA、MDL、SPR、WAV、天空盒六面放进去，
   子目录随意组织。
2. 以下任一处选择该文件夹，确认“建立资产库”后会生成目录文件并扫描：
   - 欢迎页 **Asset library…**（不需要打开工程，只查看和扫描库）；
   - 工程窗口 **Library → Attach Asset Library…**；
   - Asset Browser 来源切到 **Asset Library** 后的 **Choose Asset Library…**。
   选错文件夹时不会写入任何东西：只有确认后才会建立目录。
3. **Library → Check for Asset Updates…** 只读取目录表；**Rescan Library and Check
   for Updates…** 先重新扫描文件夹再检查。资源重扫描是显式操作，打开工程不会自动
   重扫描入库或更新工程快照。
4. 工程窗口监视已关联的库，独立资产库窗口监视当前库；发现文件或目录变化时，
   工程底部状态栏或资产库窗口会提示重新扫描。往库里加文件后仍需显式 **Rescan**，
   才会出现在库视图与更新检查中。监视提示不会自动捕获资源或标脏工程。

库中的 WAD 容器显示为一个分组，每个纹理条目是独立资源，拥有自己的稳定 ID、
内容哈希与修订号。模型会记录 `<name>T.mdl` 外置纹理模型和声明的外部动画组，
六面齐全的天空盒会形成一个组资源并依赖六张面。只有库中确实存在的文件才会成为
依赖。

## 浏览与绑定

Asset Browser 顶部有两个选择器：内容来源（游戏文件 / 工程 / 某个资产库）和库选择。

- 选中资产库时，浏览的是库的当前内容。双击非地图资源打开只读预览，不捕获资源。
  右键 **Add to Project** 可显式复制当前修订。
- 模型、Sprite、声音可直接从库拖入工程地图：拖入只创建临时放置预览，松开后才把
  所选修订及依赖捕获进工程；取消不捕获。载荷使用资源 ID 与修订，跨工程或过期
  载荷会被拒绝。
- 纹理拖入地图会捕获所选修订，并把鼠标下的面（没有命中时用已选的面）的材质改成该
  纹理名；同一次拖放只产生一步原生撤销。一个工程 WAD 里嵌入多张纹理时没有唯一名字，
  拖放会拒绝并提示先拆分。
- 天空盒以“组 + 六面”的形式出现在浏览器里，条目提示会标明 Skybox (6 faces)。拖入
  地图会一次性捕获组和六个面，并把 worldspawn 的 `skyname` 设成该组的基名；同样只
  产生一步原生撤销。天空盒没有单张预览图，双击不会打开预览。
- 已经绑定的库资源会同时显示工程修订号、发布路径与更新状态；工程来源的拖放
  使用已捕获修订及其发布路径，库来源使用本次选中的库修订。
- 切换内容来源时，模型、纹理、Sprite、声音预览随来源与修订更新。库预览读取库当前修订，工程来源仍使用
  已捕获快照；预览生成或解码失败时，将鼠标停在资源上可查看失败提示。
- 右键 **Use Current Library Version** 显式刷新快照，**Find Uses in Project**
  列出该资源在工程地图中的使用位置。

解绑后库文件消失或损坏都不影响工程：工程保存的是内容快照，地图、预览、编译都不
再需要原库。

## 更新与忽略

**Library → Check for Asset Updates…** 打开审阅对话框，列出每个已绑定资源的工程
修订、库修订、状态与地图使用次数（悬停显示具体位置）。

- 勾选后 **Update Selected** 一次性更新所选资源；更新在单个存储事务内完成，
  任何一个失败则全部保持旧修订。资源沿用原 ID，所有地图引用同时生效，旧修订仍可
  在历史中恢复。
- **Ignore This Version** 只忽略当前库版本，之后库再次变化仍会提醒。
- **Remind Me Later** 只对当前会话生效，下次打开工程会重新提示。
- 缺库、资源被删除或不可读只影响状态显示，不会自动修改工程。
- 只改了依赖、内容没变时也会提示（“库中的依赖已变化”）：例如库为某个模型新增了
  配套文件。更新会补捕获这些依赖并重写依赖图，主体内容修订保持不变。

库出现新版本不会自动改写任何工程；同一资源在不同库中同名但内容不同时直接报冲突，
需要手动处理。

## 导入与使用内容

支持 MAP、MDL、SPR、WAV、TBPREFAB、WAD 和 PNG/BMP/TGA/JPG 图片。
内嵌内容随工程保存，不依赖导入原文件继续存在。

GoldSrc 图片导入时指定纹理名，预览自动缩放、减色及透明处理，再确认导入。
转换结果为包含四级 mip 的 256 色 WAD3 纹理；尺寸限制为 512 以内的 16 倍数。
`{` 前缀启用二值透明，alpha 阈值为 128。工程同时保留原图和转换参数。
导入的 WAD 与转换后的纹理自动用于工程地图，可在面检查器中选用。
主 Asset Browser 当前显示 WAD 的首张可解码纹理作为预览，尚不支持拖放 WAD 卡片贴图。

从资产库捕获的模型会自动带上分离纹理文件（`xxxT.mdl`）和外置动画组
（`xxx01.mdl` 等）；GoldSrc 模型的内嵌纹理本来就在模型里，不会额外捕获同名图片。
捕获天空盒会带上六面。整个闭包在一个事务里提交，任何一个依赖失败都不会留下半成品。
直接导入原生模型、Sprite、声音与预制件按原文件保存；Sprite 帧、WAV 引用等仍需
自行补齐，不能据此认定工程已收集地图的全部依赖。其他类型也不会仅因导入成功就
标记为“引擎验证通过”。

**Asset → Reimport…** 替换所选内容并保留身份；工程内引用使用同一游戏路径，
已打开地图与预览会刷新。外部原文件的修改不会自动覆盖工程内容。
**Rename…** 改显示名称，**Move…** 改虚拟路径；两者均保留首次导入的游戏路径。
当前默认导入路径为 `maps/`、`models/`、`sprites/`、`sound/`、`textures/` 或 `prefabs/`
加文件名，尚未提供完整的游戏路径映射编辑器。

## 编译快照

工程地图的编译输入是导出的固定快照目录，内容为：

- `map.map`：当前地图内容。
- `textures.wad`：只含该地图按名字实际引用、已转换为 GoldSrc 兼容格式的纹理。
  导入的整包 WAD 也只导出被用到的那几张。
- `wads.cfg`：供 hltools `-wadcfgfile` 使用的 WAD 列表。
- `snapshot.txt`：工程 ID、地图修订、每个资源的 ID/修订/内容哈希、`direct`/
  `dependency` 标记、纹理清单，以及 `external`（编译器工具纹理与 `gfx/env` 天空盒面）。
- `resources/<发布路径>`：被引用的模型/Sprite/声音及其工程依赖闭包。

如果引用的纹理缺失、歧义、路径非法或地图无法扫描，导出会**直接失败**并指出具体
引用、地图与行号，不会生成一个贴图不全的 BSP。捕获这些资源后再导出即可。

在快照目录内运行即可，不需要资产库，也不需要打开 TB：

```powershell
cd <snapshot>
hltools compile -wadcfgfile wads.cfg map.map
```

hltools 默认把地图用到的纹理嵌入 BSP，未使用的资源不会进入 BSP；`bsp info`
会显示嵌入纹理数。vis 阶段需要 `.prt`，与快照无关。

**从工程窗口编译**时不需要手工导出：每次运行编译配置都会先导出一份新的快照到独立
目录，并把 `${MAP_DIR_PATH}`、`${MAP_FULL_NAME}`、`${MAP_BASE_NAME}` 指向这份快照。
地图文件沿用工程里的名字（例如 `alpha.map`，而不是 `map.map`），所以按 `${MAP_BASE_NAME}`
派生输出名的现有配置不用改。编译进程的工作目录也解析到快照里，配置中的相对路径
（例如 `-wadcfgfile wads.cfg`）同样落在快照目录。快照在这一轮运行期间不会被编辑、
切换标签或库更新改写。

快照目录是一次性的：编译产物写在里面，对话框关闭后随之删除，因此发布流程仍应像普通
TrenchBroom 一样用复制任务把 `.bsp` 拷到游戏或 mod 目录。需要长期保留的输入请用
**File → Export Compile Snapshot…** 显式导出。

## 保存与版本

- 地图窗口的 **Save / Ctrl+S** 与工程窗口 **Save Project** 都保存整个工程，包含
  其他已打开地图的修改。标题中的修改标志反映工程状态。
- **Save Project Copy…** 输出当前完整副本，不切换当前工程，也不清除当前修改标志。
- 工程资源的导出副本用于取出兼容结果；独立 MAP 使用地图窗口的导出功能。
- 关闭地图时可保存整个工程或丢弃该地图尚未保存的编辑。关闭工程前先关闭地图，
  工程本身还有修改时会再次询问保存。
- **History → Create Version…** 建立命名节点，包含当前未保存的地图内容。
  随后保存工程才能将该节点持久写回原文件。
- 选择版本后可比较当前状态，查看发生变化的资源/地图与依赖数量。
  这还不是几何或图片的可视化差异查看器。
- 关闭工程地图后可恢复版本。恢复前自动保存当前目录状态为安全版本，恢复结果
  仍需保存工程。地图窗口中已丢弃的编辑不属于安全版本。

同一工程使用锁防止被两个会话同时编辑；保存还会检查原文件是否被外部改动。
冲突时保留当前工作状态，改用保存副本，不覆盖外部版本。

## 后续工作

- 地图引用改为资源 ID（引用解析层），不再依赖发布名不变；同名纹理与精确使用位置。
  目前审计与拖放已经走统一解析层，地图文件本身仍保存名称。
- 库内直接维护已转换的兼容纹理。
- 原生对象树和对象变换持久化，跨地图预制件联动及实例覆写。
- 天空盒的引擎 `gfx/env` 布局发布产物，Sprite 帧与 WAV 引用等依赖捕获。
- 同名资源跨库冲突的图形化解决流程，库目录移动后的重新指向。
- 转换设置再编辑、更多资源导入器、多套编译配置与面向 CS 1.6 的完整发布闭环。
- 增量保存、大工程性能验收、历史清理与只读工程模式。

当前仍需要对应游戏配置；`.tbproj` 不直接供 GoldSrc 游戏运行。
工程内地图仍使用 MAP 序列化，独立旋转/缩放数值的持久化尚未因此解决。
