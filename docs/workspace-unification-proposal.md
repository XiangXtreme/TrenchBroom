# 工作区功能整合方案

日期：2026-11-08

状态：第一轮与第二轮已交付；按后续确认追加实体浏览器迁移和独立实体检查器移除。面材质与其余资源轮次仍按后文推进。

本文细化[功能与工作流清单](workspace-function-workflow-inventory.md)，与现行
[工作空间 UI 架构](workspace-ui-architecture.md)共同使用：后者负责宿主、上下文、生命周期
和布局，本方案负责用户入口、能力对照与迁移验收。控件外观遵循
[UI 组件样式治理](ui-component-style-governance.md)。

## 确定的方向

1. 场景树和实体属性以右侧同屏为主要工作方式；实体属性统一在场景页；原实体命令和 Ctrl+2 重定向到场景与属性。树和属性可调整比例、各自展开或收起，在窄屏仍可独立使用。
2. 材质选择统一到底部 Content Browser，右侧 Face 专注面属性和 UV。底部必须先具备原生材质浏览全部必要能力，才能迁移原入口。
3. 统一是统一操作和数据语义，不要求把所有资源变成同一种对象，也不要求把库管理、地图设置和地形工具塞进同一列表。插件和原有游戏格式继续可用。

## 合并后的工作区

下面按区域说明整合职责。场景树、共享属性和实体定义浏览迁移已经实现；面材质和其余资源工作流仍按后续轮次推进。

| 区域 | 建议内容 | 使用结果 |
| --- | --- | --- |
| 右侧场景 | 图层、组、实体及对象树；搜索、排序、显隐和锁定；下方属性与变换 | 选择对象后同屏检查和编辑；可单独扩大树或属性区域。图层操作集中此处，地图页的原入口可作为跳转或兼容视图。 |
| 实体入口 | Ctrl+2 打开右侧场景与属性；“显示实体浏览器”打开底部实体分类 | 右侧保留一个属性入口，定义浏览、说明、创建和 FGD 设置在底部完成。 |
| 右侧面 | 面属性、UV 和面标志；打开底部材质浏览的入口 | 不再长期占据右侧空间显示另一套材质列表；`Ctrl+3` 仍直达面编辑。 |
| 右侧地图设置 | 地图边界、Mods 等地图级配置 | 原 `Ctrl+1` 仍可到达地图设置与图层管理，导航迁移必须保留可发现性。 |
| 右侧 Terrain | 创建、编辑模式、笔刷、材质槽、分析、预算和导出 | 保留独立工具会话；资源入口定位到底部匹配的 Terrain Material，工具切换不重置正在使用的设置。 |
| 右侧插件 | 已注册插件面板和关闭操作 | 保留注册、卸载和生命周期；底部 Extensions 可继续跳转。 |
| 底部 Content Browser | 来源、类型、搜索、预览、详情；实体类型已迁入，地图材质集合视图和面材质应用能力待后续整合 | 一个主要浏览区域承载地图材质、工程、库和游戏文件；根据来源与目标显示适当操作，不假装不同资源具有同样能力。 |
| 底部其他工具 | Output、Python、Issues | 保留文档作用域、抽屉/固定、焦点和快捷键。 |
| Asset Library | 导入、转换、创建复合材质、重命名、删除和批量管理 | 仍是库管理工作区；从 Content Browser 定位进去，也能返回原资源。 |

默认应保持地图视口可用：底部浏览器可抽屉或固定，面编辑与浏览可同时可见；显式打开浏览器、拖放资源或打开对话框时，不应因为短暂焦点变化丢失操作。资源详情、浏览器选择、地图选区和活动文档分别是不同状态。

## 关键工作流

### 选择对象和管理图层

在视口或场景树选择对象，另一处同步选择；右侧显示目标、变换及属性。需要空间时收起树或属性，原实体入口可直达同一编辑能力。图层菜单与拖放调用同一命令，删除图层的对象归属、当前层变化和事务必须与现有行为一致。多选、混合值、隐藏或锁定节点，以及过滤状态下的选区均需明确测试。

### 选择和应用面材质

选择面后打开底部浏览器的地图材质视图，搜索、按集合分组或按使用量定位，选择后对原目标执行地图命令；无选面时仍可设置当前材质。右侧继续显示面属性。工程资源选择涉及捕获时，先检查来源、冲突和目标；取消或目标变更不得误修改另一张地图。此工作流需支持鼠标、原有导航与键盘路径，避免每次选择都强迫用户重新打开或重新搜索。

### 使用库资源与 Terrain 材质

浏览和预览不捕获、不标脏工程。明确应用库资源时先处理捕获及冲突，再执行对应地图或地形操作；已捕获的工程快照与库原件分别标明来源和状态。地图 Undo 撤销地图编辑，不自动删除已捕获的工程快照。库不可用、资源被删除、版本变更、冲突取消、依赖缺失和目标失效时应显示原因并保持原目标内容。

Terrain 的推荐路径是从材质控制打开底部浏览器并筛选 Terrain Material，用户选择后明确捕获并绑定，再返回绘制槽；同样允许管理库材质。实现前需确认捕获及绑定的事务边界、失败补偿和目标变化处理；不要把普通纹理应用到 Terrain Material 槽。

### 工程、独立地图和切换目标

工程浏览器可在无活动地图时查看资源；需要地图的命令禁用并说明原因。独立 MAP 使用对应游戏的材质集合，不依赖工程资源功能。切换地图时界面显示当前目标；模态选择、拖放或异步预览启动后必须固定并校验原始目标及资源修订，失效时停止，不能回退到新活动地图。搜索、选择与焦点的保留范围应在实施时明确并测试。

## 按可试用功能分轮交付

每轮交付完整的可运行 Release 版本、独立提交、自动验证记录和简短试用清单；交付后供用户实际作图验证，后续按反馈推进。本次按用户要求完成到第二轮，第一、二轮一并交付；第三至第五轮继续分轮推进。

基线核对、共享命令提取、测试和旧实现清理放在相应功能轮次内完成，不单独占用用户试用的一轮。每轮只移除已被完整替代并验证的实现；保留的兼容入口委托同一实现。布局设置采用现有版本化机制，异常时可恢复默认布局。

| 轮次 | 可试用的交付 | 用户主要验证 |
| --- | --- | --- |
| 第一轮：场景树 | 可承担日常场景组织的树与图层操作 | 找对象、选对象、分组及移动、图层管理、撤销、重开 |
| 第二轮：场景树与完整属性 | 同屏选择和编辑；旧实体入口访问同一能力 | 变换、实体属性、多选、FGD 与智能编辑器、快捷键 |
| 第三轮：底部材质工作流 | 材质选择迁入底部，右侧专注面属性和 UV | 连续贴图、临时替换、材质集合、定位和 UV |
| 第四轮：通用资源选择 | 属性字段、浏览器及库之间连续的选择与应用 | 模型、声音、天空盒等按类型验证；捕获、取消和跨地图目标 |
| 第五轮：Terrain 资源闭环 | 从浏览、捕获到绑定复合材质并绘制 | 三槽绘制、依赖、缺失反馈、雕刻状态和编译导出回归 |

### 第一、二轮交付记录（2026-11-08）

使用入口：右侧原 Outliner 改名为“场景”。没有已保存布局时默认打开场景；已有布局继续恢复原页面，重置布局后使用新默认。原地图、实体、面入口与 `Ctrl+1/2/3` 保留。

- 场景树保留搜索、视图排序、层级拖放、显隐和锁定。树选项增加展开、折叠、定位所选对象和收起树；属性可通过独立按钮收起，两部分不能同时隐藏。分隔比例与可见性继续使用现有布局设置。
- Map 页与场景树通过 `LayerActions` 共享图层菜单、启用判断和删除事务，场景树也可调整实际图层顺序。删除非空图层将对象移到默认层，撤销恢复对象与当前层。新建图层提示准确描述为空层创建。
- 手动展开状态保留在当前树实例中，选择对象不再主动折叠组和 brush entity。全量刷新保留滚动，搜索清除后恢复搜索前展开与滚动；显隐、锁定和实体改名会更新正在使用的过滤与排序。
- 场景和实体页复用 `SelectionPropertyEditor`，提供“表单／表格”。显示方式随偏好同步，编辑始终指向各自地图。表单保留变换卡、FGD 友好名、原始键和内联编辑；变换卡默认收起以先显示实体字段，可随时展开。表格复用原生完整属性表与智能编辑器。两种页面按需创建。
- 表格可重命名键、增加和删除属性、设置保护属性、显示默认值，以及设置现有、缺失和全部默认属性；FGD 说明、flags、choice、颜色、WAD、模型、声音和天空盒等继续走原生智能编辑路径。复杂操作通过表格呈现，不需要跳回旧实体页。
- 混合类型也能查看和编辑属性。表单与表格共用键和值可编辑判断，智能编辑器同步遵守 FGD 只读与链接组约束。WAD 专用管理入口保留其区别于原始键编辑的规则。
- 同一选区的普通属性值变化复用现有行；字段增加、删除或类型变化才重建。输入控件正在使用时延迟同选区结构刷新，真实选区切换仍更新目标。颜色和模型文件选择结束后校验原选区及控件生命周期。

本轮验收覆盖 `LayerActions`、`SelectionPropertyEditor`、Outliner、属性模型/表格、变换、地图窗口与工程窗口；新增 4000 实体场景连续搜索/清除且保持节点及地图选区的回归。快照增加 `outliner-properties-table` 与 `outliner-properties-narrow`，用于检查完整属性与窄面板。

### 第二轮追加：实体浏览器迁入底部

使用入口：底部 Content Browser 的内容类型选择器增加“实体”，与纹理、模型、声音等并列。视图菜单提供“显示实体浏览器”。右侧独立 EntityInspector 页面与实现移除；原实体命令及 Ctrl+2 打开“场景与属性”，保存的旧 Entity 页面迁移到场景，不改变其他页面设置。

- 实体页使用“类型列表＋定义说明/点实体预览”，支持名称及说明搜索、点/刷子筛选、名称/使用量排序、分类分组与已使用过滤。浏览类型不修改地图或选区。
- 点实体可从列表或预览拖入 2D/3D 视图定位放置；“在当前视图创建”沿用原生视图计算位置。刷子实体须先选择几何，再执行“将选区转为实体”。两条路径沿用原生命令与撤销。
- FGD 定义文件设置放在实体页“定义文件…”中。窗口归属当前地图页；切换地图时关闭旧设置窗口并释放旧预览。无活动地图可浏览游戏定义，创建与定义配置禁用。
- 项目只保留一个 Content Browser，实体页随活动地图更新；文件资源浏览状态保留。相同文档的初始化通知不会重建实体页。
- 创建完成显示场景属性。表单中的 classname 提供可搜索补全，修改已有实体类型无需转到底部重新创建。

追加试用步骤：

1. 在独立 MAP 和工程地图分别打开底部“实体”，搜索 light，阅读说明，拖入 2D、3D 视图，验证取消拖动、放置和 Undo/Redo。
2. 选择几个刷子，筛选刷子实体并选择 func_door，执行转换，验证属性、归属与 Undo/Redo。
3. 在场景表单直接修改 classname，检查搜索补全和撤销；切换表格继续编辑同一对象。
4. 从实体页打开 FGD 设置，切换两张使用不同定义的工程地图，确认列表和创建目标跟随；关闭全部地图后确认创建禁用。
5. 在实体和其他内容类型之间切换，检查原资源搜索、详情、项目来源和模型/声音预览继续可用。

- Release 应用及 UI 测试构建通过；18 个修改编译单元通过 clang-cl 严格检查，19 项 CTest 全部通过，涵盖实体浏览、工程地图绑定、原模型/sprite 预览和完整属性编辑。
- 原生窗口模式下，实体创建/刷子转换及 Undo/Redo、右侧导航与焦点用例共 145 条断言通过。列表的点实体拖放载荷有回归覆盖；完整鼠标拖入 2D/3D 与取消路径仍按上述试用步骤人工确认。
- components、实体页及空结果、workbench、工程抽屉/地图切换、场景树/属性表格在 Light、Dark、Blender 三主题 100% 比例下共 24 张快照通过捕获完整性检查；已单独检查实体页和工程面板原尺寸截图。未使用已批准的像素基线做差异验收。
- 样式治理通过；中英离线手册同步并更新翻译指纹，GenerateManual 和 14 对章节结构/生成结果校验通过。

### 第一轮：先把场景树做好

目标：用户能用场景树完成一张真实地图的对象与图层组织。

- 核对并完善树中图层、组、实体、brush 及 Terrain 现有结构的展示和识别，清晰标识当前层、选择、显隐和锁定状态；Terrain 继续按原有组织与数据语义工作。
- 树与视口选择双向同步，单选、多选、定位及过滤后的选择行为清楚；搜索清除后恢复合理展示，不意外改变地图选区。
- 完成创建/激活图层、移动选区、全选、隔离、显隐、锁定、导出排除、重命名、删除和用户图层顺序。共享 Map 页与树的图层命令、启用条件及事务，明确区分视图排序与地图实际顺序。
- 核对组、实体、brush 在不同父节点间拖放的合法性、链接组约束和撤销；不合法目标应有明确反馈，不能丢失或重复对象。
- 修正新建图层提示与实际行为的不一致；本轮不默认增加“从选区创建”新语义。
- 处理展开状态、滚动、窄面板布局及常规操作中的局部刷新；用真实大型地图检查搜索和选择响应。

范围边界：属性暂时复用现有能力，保留 Entity 和已有 Outliner 属性入口；完整属性统一放第二轮。Face、底部材质选择及 Terrain 专用工具继续沿用现有流程。图层旧入口保持可达，避免在场景树试用时同时改变其他主要工作流。

用户试用步骤：

1. 打开一张已有地图，创建 Buildings、Details 两个层，把几个对象移入并切换当前层。
2. 在树和视口交替进行单选、多选、查找及定位；搜索后继续选择，再清空搜索。
3. 隐藏、锁定和隔离图层，调整图层顺序；检查普通显示排序不会改写实际层顺序。
4. 拖动允许移动的对象到另一个层或组，尝试不合法拖放，逐步撤销和重做。
5. 删除非空图层，确认其对象按原有规则保留；保存重开并检查结构、对象和导出设置。
6. 在工程两张地图间切换、关闭后台标签，再在独立 MAP 重复关键操作；缩窄右侧并检查可用性。

完成条件：上述流程没有选区错乱、对象丢失、重复节点、错误重挂或撤销异常；常用操作不持续重置展开/滚动状态。Release 构建、相关 Outliner/图层/工程绑定回归和三主题代表快照通过，提交实测记录。用户能据此单独判断第一轮是否适合日常使用。

### 第二轮：场景树与完整属性同屏

目标：在第一轮场景树中选中对象即可完成常见属性编辑，原实体入口和快捷键继续可用。

统一属性能力，覆盖受保护属性、增删及键操作、现有/缺失/全部默认值、FGD 说明、变换、混合值、只读和链接组约束；复用 flags、choice、颜色、WAD、模型、声音、skybox 等智能编辑规则。树和属性可调整比例或分别收起，窄屏可独立编辑属性。原 `Ctrl+2` 及实体定义浏览保留。

用户试用：在同一地图中修改门、灯光和 worldspawn；复制并多选不同属性值的灯光，检查混合值、批量编辑和撤销；切换友好名/原始键，使用默认值及保护属性；从旧实体入口重复操作，检查结果一致；收起树、拖动分隔条并重开。

完成条件：原两套属性能力对照无未处理缺口，未通过的能力不能靠移除入口掩盖；属性回归、焦点/键盘和布局实测通过。只有这一轮具备完整能力后，才收敛被替代的属性实现。

### 第三轮：把材质选择完整迁到底部

目标：右侧负责面属性和 UV，底部完成找材质、选材质和连续贴图。

底部先达到原生材质浏览能力对等，覆盖搜索、名称/使用量排序、集合分组、已使用过滤、图标尺寸、定位、材质集合/WAD 设置、非 GoldSrc 格式和当前材质语义。保留无选面设置当前材质与同材质切换行为，任何交互调整先明确。覆盖 GL 资源加载和销毁后再迁移 Face 浏览入口。

用户试用：给一栋建筑连续贴墙、地面和屋顶，固定底部并连续搜索，右侧调整 UV；用抽屉临时替换一面材质；定位当前材质、切换已使用过滤、检查无选面操作；保存重开并测试工程、独立 MAP 及非 GoldSrc fixture。

完成条件：连续贴图不反复丢失搜索或滚动，不被迫每选一次就重开；原生材质能力全部可达，UV、当前材质和撤销结果正确。材质真实 fixture GPU-ready 验收、预览与生命周期回归和三主题布局通过后，右侧旧材质列表才退出主要界面。

### 第四轮：贯通通用资源选择

目标：在浏览器找资源，在属性字段明确选择资源，在资源库管理资源，三者路径连贯。

统一资源身份、来源、预览、定位和选择上下文；逐种核对模型、sprite、声音、天空盒、纹理、prefab 和地图已有动作，保留各自差异。明确浏览不捕获，应用/捕获有目标；处理冲突、取消、库失联、快照、修订、异步失效和多工程隔离。结合工作空间架构处理无地图浏览对后备文档的耦合，仅在本轮真实需要的职责范围内提取服务。库管理仍保留导入、转换和批量管理。

用户试用：从声音属性试听并选择，从模型相关入口选择资源，设置天空盒；预览库资源后取消，检查工程未意外标脏；实际使用后确认工程快照；测试冲突取消、切换地图、关闭原目标、无地图浏览和库断开。不同类型按其已有能力分别验收。

完成条件：目标始终明确，不向新活动地图误写；浏览、捕获及地图 Undo 边界正确；资源类型与原有入口回归通过，并完成人工拖放、模态和焦点验证。

### 第五轮：贯通 Terrain 材质工作流

目标：从 Terrain 发起材质选择，在底部找到复合材质，捕获并绑定后直接继续绘制。

复用第四轮资源上下文，支持工程和库的 Terrain Material 定位、捕获及绑定；保留默认三通道、依赖纹理、缺失/非法反馈和三个绘制槽。明确捕获与地图绑定的事务及失败边界，不把普通纹理当作复合材质。保留笔刷设置、地形分块、雕刻、顶点编辑和编译时实体配置。

用户试用：创建或转换地形，选择库材质并捕获绑定，分别绘制三槽；切到场景树再回到 Terrain，继续雕刻和绘制；测试取消、依赖缺失、材质无效及切换地图；撤销绑定和绘制，检查已捕获快照仍保留；分析预算并生成编译快照，确认编辑分块与编译配置保持正确。

完成条件：资源选择到绘制的路径连续，错误状态可恢复，工具状态不意外重置；Terrain 原功能、编译导出及资源依赖回归通过。最终跨轮走一遍建图、组织、属性、贴图、Terrain、保存重开和编译流程。

## 各轮共同验收门槛

每批至少运行对应 `TbUiLibTest`、受影响的资源/预览测试与 Release 构建；UI 变更执行样式治理检查、三主题代表场景快照及相关预检。新建或扩展测试覆盖地图切换、关闭后台标签、异步失效、资源捕获与撤销边界。原生桌面验收覆盖焦点、拖放、弹窗及窗口切换；截图或后台测试不能单独证明这些行为。对大量节点和大材质集测量打开、搜索和切换响应，避免统一后重复加载、全树重建或阻塞 UI。

## 尚待产品与实测确认

- 底部材质视图默认采用哪种密度、是否自动随选面定位，以及选中同一材质切换无材质的交互是否需要显式提示；实施前通过原型讨论，不能静默改变现有语义。
- 场景树与属性面板的默认比例、窄屏最低可用高度、是否记住各地图或整个工作空间的展开状态。
- 地图设置入口与图层跳转的具体呈现；保留快捷键不等于强制保留完全相同的页面布局。
- 单独 MAP 与工程在所有资源类别、游戏配置和拖放路径的实测差异；Terrain 从库创建到捕获绑定的现有详细步骤。
- 合并后对原有插件、用户布局及依赖控件名称的测试/自动化的影响，需在实际迁移时核对。
