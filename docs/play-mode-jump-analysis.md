# Play 跳跃 HUD

更新：2026-11-11。

## 显示方式

按 F7 进入 Play 后，HUD 按当前跳跃展示三组信息：

- 起跳提示：动作类型、接地帧数 FOG、接地水平速度与起跳后的水平速度。
- 右侧逐段表：方向键、Gain、Loss、物理帧数、增速帧比例；蹲伏状态显示在表下。
- 落地结果：动作类型、三位小数距离、Prestrafe（括号内为 FOG）、Strafe 数。
  失败穿过起跳高度时显示“失败（估算）”，距离截止于同高平面。

明细随物理命令更新，结果默认停留 4 秒后淡出。设置 → KreedzBroom → 跳跃分析
控制成绩、失败结果、Strafe 明细和停留时间，并沿用 HUD 总开关。

## 动作与数值

支持独立 LJ/HJ，同高接跳 Bhop、Stand-Up Bhop、DuckBhop，以及实际蹲弹起后接跳的
CJ、SCJ、DCJ、MCJ。分类使用真实接地、离地和蹲姿变化；原地蹲起不作为 CJ。
相邻动作最多间隔 10 条接地命令，FOG 是物理命令数。
落差、长时间地面移动、碰墙、顶头、斜坡、水、梯子、传送和辅助移动会终止动作链。

跳跃距离为水平中心位移加 32 units，同高脚底容差为 0.125 units。
成绩范围为 120–280 units，Bhop / SBJ / DuckBhop 下限为 150。
几何平台间隙与跳跃成绩分开计算；平台测距仍仅着地显示 160 ≤ 间隙 < 300。

Prestrafe 是起跳命令前水平速度，起跳后速度包含地面摩擦及原生 stamina 处理。
每次方向键按下到松开为一段；W/S/A/D 均支持。多个键重叠时，最早按住的键获得
Gain / Loss，避免重复累计。每段百分比为增速帧占该段物理帧的比例。
起跳命令的地面速度变化不计为空中增速。

## 实现与验证

PlayModeTimeline 中的 PlayModeJumpStats 统一读取 scs_step_observed 的命令、
前后状态与碰撞摘要，供实时 HUD 和当前落地结果使用。显示不改变移动算法。

落地距离使用首次地面碰撞位置，避免落地后的水平滑动计入；2 units 吸附落地用
hull trace 校正。站立和蹲伏统一换算为脚底高度，避免虚假 18 units 高差。
腾空最后一条命令的按键统计按完整命令计算，失败距离在同高平面插值。

单次跳跃最多计算 64 段 Strafe 和 5000 条空中命令。HUD 显示最近最多 10 段，
超出时显示省略提示；表格共用一个文字渲染器。
Hook / Noclip 后需恢复正常地面移动且前后速度低于 260 才接受成绩。
CP、传送、失焦和长卡顿跳步会中止当前计算。

回归使用真实碰撞世界与原生移动命令，覆盖 LJ/HJ、失败估算、蹲姿转换、
Bhop/SBJ/DuckBhop、CJ/SCJ/DCJ/MCJ、动作链失效、辅助移动、按键重叠归属，
以及不同渲染节奏下的结果一致性。

参考用户提供的 KZ-Rush 反编译源码、本地 UQ 插件及内嵌 ReGameDLL 移动逻辑。
反编译存在失真，未复制其实现。原插件同参数、同输入逐帧对照尚未完成，
不能将显示的小数精度等同于服务器成绩一致性。
