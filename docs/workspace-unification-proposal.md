# 工作区功能整合方案

日期：2026-11-08

状态：基于代码走读的方案；导航方向已与用户确认，尚未实施或完成人工工作流验收。

本文细化[功能与工作流清单](workspace-function-workflow-inventory.md)，与现行
[工作空间 UI 架构](workspace-ui-architecture.md)共同使用：后者负责宿主、上下文、生命周期
和布局，本方案负责用户入口、能力对照与迁移验收。控件外观遵循
[UI 组件样式治理](ui-component-style-governance.md)。

## 确定的方向

1. 场景树和实体属性以右侧同屏为主要工作方式；原实体入口和快捷键继续可用，指向同一套属性能力。树和属性可调整比例、各自展开或收起，在窄屏仍可独立使用。
2. 材质选择统一到底部 Content Browser，右侧 Face 专注面属性和 UV。底部必须先具备原生材质浏览全部必要能力，才能迁移原入口。
3. 统一是统一操作和数据语义，不要求把所有资源变成同一种对象，也不要求把库管理、地图设置和地形工具塞进同一列表。插件和原有游戏格式继续可用。

## 合并后的工作区

名称与排列仍可通过原型验证调整，下面描述职责和目标，而不是已经存在的界面。

| 区域 | 建议内容 | 使用结果 |
| --- | --- | --- |
| 右侧场景 | 图层、组、实体及对象树；搜索、排序、显隐和锁定；下方属性与变换 | 选择对象后同屏检查和编辑；可单独扩大树或属性区域。图层操作集中此处，地图页的原入口可作为跳转或兼容视图。 |
| 右侧实体入口 | 直接显示同一属性编辑能力和实体定义浏览 | 原 `Ctrl+2` 及既有入口仍可找到实体属性和定义；需保证窄屏可用，不要求同时占用树空间。 |
| 右侧面 | 面属性、UV 和面标志；打开底部材质浏览的入口 | 不再长期占据右侧空间显示另一套材质列表；`Ctrl+3` 仍直达面编辑。 |
| 右侧地图设置 | 地图边界、Mods 等地图级配置 | 原 `Ctrl+1` 仍可到达地图设置与图层管理，导航迁移必须保留可发现性。 |
| 右侧 Terrain | 创建、编辑模式、笔刷、材质槽、分析、预算和导出 | 保留独立工具会话；资源入口定位到底部匹配的 Terrain Material，工具切换不重置正在使用的设置。 |
| 右侧插件 | 已注册插件面板和关闭操作 | 保留注册、卸载和生命周期；底部 Extensions 可继续跳转。 |
| 底部 Content Browser | 来源、类型、搜索、预览、详情；增加当前地图材质集合视图和面材质应用能力 | 一个主要浏览区域承载地图材质、工程、库和游戏文件；根据来源与目标显示适当操作，不假装不同资源具有同样能力。 |
| 底部其他工具 | Output、Python、Issues | 保留文档作用域、抽屉/固定、焦点和快捷键。 |
| Asset Library | 导入、转换、创建复合材质、重命名、删除和批量管理 | 仍是库管理工作区；从 Content Browser 定位进去，也能返回原资源。 |

默认应保持地图视口可用：底部浏览器可抽屉或固定，面编辑与浏览可同时可见；显式打开浏览器、拖放资源或打开对话框时，不应因为短暂焦点变化丢失操作。资源详情、浏览器选择、地图选区和活动文档分别是不同状态。

## 能力对照与整合条件

| 项目 | 现状与差异 | 迁移前必须做到 |
| --- | --- | --- |
| 图层 | 两套菜单重复调用地图命令；两处新建均创建并激活新层。Map 按钮提示从选区创建，但代码未移动选区。Layer Editor 有上下调整图层顺序；Outliner 有层级、搜索、文件/类型排序和节点拖放。 | 共享命令、启用条件和事务；保留新建、激活、移动选区、全选、显隐、隔离、锁定、导出排除、改名、删除、用户层顺序和拖放。明确区分视图排序与实际层顺序。修正误导提示；若新增“从选区创建”，须作为明确命令并测试其撤销。 |
| 属性编辑 | Entity 的属性表支持受保护属性、增删、设置现有/缺失/全部默认值及智能编辑器；Outliner 属性提供变换卡、FGD 友好名/原始键、混合值和内联编辑。两套实现并不等价。 | 同一属性能力覆盖普通键值、添加/删除、受保护属性、默认值操作、FGD 定义和说明、只读、单选/多选/混合类型、worldspawn、链接组约束、键盘与撤销；保留变换卡。逐项对照键重命名、排序及快捷操作，未确认前保留旧入口。 |
| 智能属性 | 原 manager 根据条件选择 flags、choice、WAD、颜色、model、特定实体声音、worldspawn skyname 和默认编辑器；Outliner 内联实现 choice、颜色、flags、WAD、skybox 和模型等，并非简单同一套。 | 使用可复用的选择规则和编辑能力，逐项保留 FGD 匹配条件、资源选择、混合值及错误反馈。不能仅凭按钮名称相同就移除原实现。 |
| 实体定义 | Entity Browser 浏览实体类别与定义文件设置；它的对象是 FGD 定义而非文件资源。 | 保留查找定义、创建相关操作和配置入口；可共享搜索交互，不把定义伪装成项目资产。 |
| 面材质 | 原浏览器提供按名称/使用量排序、集合分组、已使用过滤、搜索、图标尺寸及定位材质；集合设置与游戏格式有关。工程另有资源选择器。 | 底部覆盖上述能力、材质集合/WAD 设置及非 GoldSrc 游戏；从选面定位当前材质。原生浏览器有重要语义：选同一材质可切换到无材质；无选面时改变当前材质。应明确保留并验证，而不只是提供“应用”按钮。 |
| Content Browser | 工程有库、工程和游戏来源，资源类别包括地图、纹理、Terrain Material、模型、sprite、声音、天空盒及 prefab；独立 MAP 走另一宿主路径。贴图/天空盒应用、资源拖放和选择器有不同条件。 | 资源类型分别定义浏览、预览、选择、应用、拖放及禁用原因；不能承诺每种资源都有相同操作。工程、独立 MAP、无活动地图都验收，不依赖虚构地图来决定操作目标。 |
| Terrain Material | Terrain 当前从工程资源选择复合材质 ID，并使用三个绘制槽；资源库可创建材质，Content Browser 可筛选，缺失材质有反馈。 | 从库浏览、捕获到工程、绑定所选 Terrain 的路径可发现；默认三通道、依赖纹理、缺失和非法状态保持可见。普通面纹理与 Terrain Material 保持各自语义。现有路径是否能一步完成须人工验证，不能当作已实现。 |

## 关键工作流

### 选择对象和管理图层

在视口或场景树选择对象，另一处同步选择；右侧显示目标、变换及属性。需要空间时收起树或属性，原实体入口可直达同一编辑能力。图层菜单与拖放调用同一命令，删除图层的对象归属、当前层变化和事务必须与现有行为一致。多选、混合值、隐藏或锁定节点，以及过滤状态下的选区均需明确测试。

### 选择和应用面材质

选择面后打开底部浏览器的地图材质视图，搜索、按集合分组或按使用量定位，选择后对原目标执行地图命令；无选面时仍可设置当前材质。右侧继续显示面属性。工程资源选择涉及捕获时，先检查来源、冲突和目标；取消或目标变更不得误修改另一张地图。此工作流需支持鼠标、原有导航与键盘路径，避免每次选择都强迫用户重新打开或重新搜索。

### 使用库资源与 Terrain 材质

浏览和预览不捕获、不标脏工程。明确应用库资源时先处理捕获及冲突，再执行对应地图或地形操作；已捕获的工程快照与库原件分别标明来源和状态。地图 Undo 撤销地图编辑，不自动删除已捕获的工程快照。库不可用、资源被删除、版本变更、冲突取消、依赖缺失和目标失效时应显示原因并保持原目标内容。

Terrain 的推荐路径是从材质控制打开底部浏览器并筛选 Terrain Material，用户选择后明确捕获并绑定，再返回绘制槽；同样允许管理库材质。实现前需确认捕获及绑定的事务边界、失败补偿和目标变化处理；不要把普通纹理应用到 Terrain Material 槽。

### 工程、独立地图和切换目标

工程浏览器可在无活动地图时查看资源；需要地图的命令禁用并说明原因。独立 MAP 使用对应游戏的材质集合，不依赖工程资源功能。切换地图时界面显示当前目标；模态选择、拖放或异步预览启动后必须固定并校验原始目标及资源修订，失效时停止，不能回退到新活动地图。搜索、选择与焦点的保留范围应在实施时明确并测试。

## 实施顺序与验收门槛

1. **建立基线**：补齐两套属性与图层命令的逐项对照，记录当前热键、焦点、图层顺序、材质选择与同材质切换；用工程及独立 MAP 实测。确认 FGD 和各游戏材质格式的差异。先修正文档与误导性提示，新增行为另行设计。
2. **共享命令与上下文**：统一图层命令、属性选择与智能编辑能力，逐步让两个入口接入；完成多选、保护属性、默认值、链接组和撤销测试后再收敛重复实现。原入口及快捷键持续可用。
3. **底部材质能力对等**：将地图材质集合接入 Content Browser，覆盖排序、筛选、定位、设置、非 GoldSrc 和当前材质语义。适配 GL 资源加载、预览与销毁；以真实地图和材质集验证后，才把 Face 浏览入口迁至底部。
4. **场景与属性布局**：按已确认方向整合同屏布局，并在宽窄窗口保留属性独立使用；迁移布局设置，保持 `Ctrl+1/2/3` 和已有插件面板。验证切换、焦点、Esc、键盘和拖放。
5. **资源工作流贯通**：完善库、工程快照、游戏文件和 Terrain 之间的定位、捕获、绑定与反馈；覆盖冲突、取消、依赖及多工程隔离。按工作空间架构逐步解除无地图浏览对后备 `MapDocument` 的耦合。
6. **清理与验收**：每批独立构建和验收；只有能力对等并完成实际工作流验证后，才移除被替代的重复 UI/实现。旧布局迁移、恢复默认布局、丢失插件和回退路径均需检查。

每批至少运行对应 `TbUiLibTest`、受影响的资源/预览测试与 Release 构建；UI 变更执行样式治理检查、三主题代表场景快照及相关预检。新建或扩展测试覆盖地图切换、关闭后台标签、异步失效、资源捕获与撤销边界。原生桌面验收覆盖焦点、拖放、弹窗及窗口切换；截图或后台测试不能单独证明这些行为。对大量节点和大材质集测量打开、搜索和切换响应，避免统一后重复加载、全树重建或阻塞 UI。

## 尚待产品与实测确认

- 底部材质视图默认采用哪种密度、是否自动随选面定位，以及选中同一材质切换无材质的交互是否需要显式提示；实施前通过原型讨论，不能静默改变现有语义。
- 场景树与属性面板的默认比例、窄屏最低可用高度、是否记住各地图或整个工作空间的展开状态。
- 地图设置入口与图层跳转的具体呈现；保留快捷键不等于强制保留完全相同的页面布局。
- 单独 MAP 与工程在所有资源类别、游戏配置和拖放路径的实测差异；Terrain 从库创建到捕获绑定的现有详细步骤。
- 合并后对原有插件、用户布局及依赖控件名称的测试/自动化的影响，需在实际迁移时核对。
