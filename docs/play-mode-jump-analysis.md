# Play 跳跃分析

更新：2026-11-10。状态：第一轮实现，后续阶段见下表。

## 当前使用

在 **设置 → KreedzBroom → 跳跃分析** 中控制成绩、失败结果与停留时间。
默认启用成绩与失败结果，显示 4 秒后淡出。沿用现有 HUD 总开关。

正常 LJ／HJ 结束后，下方中央显示类型、距离、Pre 与 Max。
错过落点、下降穿过起跳高度时，显示同高位置的“失败（估算）”；不会继续
累加到深坑底部。成功必须实际着地，不能只因越过一个高度就认定成功。

几何测距仍只在着地时显示 160 ≤ 间隙 < 300。跳跃成绩采用 KZ 的水平中心
位移加 32 units 口径，独立于几何间隙，默认显示 120–280 units 的同高结果。
站立与蹲伏都先转换成脚底高度。同高容差为 0.125 units。

HJ 根据起跳速度方向上的邻近平台边与边下落差识别，复用跳台辅助的探测。
红色 13 units 起跳建议线保持原有含义；当前不显示或推测引擎摩擦帧数。

本轮只显示独立 LJ／HJ；近期蹲动作、蹲姿起跳、尚有前次跳跃 stamina 的
起跳保留为未支持类型，不能混入 LJ 成绩。完整 CJ／Bhop 分类属于下一轮。
碰墙、顶头和斜坡接触终止当前记录，避免将受阻位移报告为干净的跳跃成绩。

## 采样与生命周期

- `scs_step_observed` 在原生移动命令执行后同步报告前后状态、量化后的输入、
  模拟时钟及碰撞摘要；长指令按现有 GoldSrc 拆分规则分别报告。
- 观测不修改第三方 `pm_shared`，不替换移动算法。底层保留落地首次碰撞位置，
  避免把剩余帧的地面滑动算入腾空距离；短距离吸附着地另作 hull trace 校正。
- `PlayModeTimeline` 逐命令向 `PlayModeJumpStats` 提供采样。ShowPre 与最终
  成绩共用离地前水平速度，计时使用模拟时钟，不依赖画面刷新频率。
- Hook、Noclip、水中或梯子状态终止记录；松开 Hook 后，必须恢复正常地面
  移动且前后水平速度均低于 260 units/s，才重新接受起跳。
- 传送、载入检查点、释放输入和长时间卡顿造成的时间轴跳步清除当前统计。
  重进 Play 重新建立采样；地图和物理配置不跨会话拼接成绩。
- 统计始终运行；显示选项仅控制呈现，不反向影响物理。当前只保存最近结果，
  不写入地图，不添加底部记录页，不在日志中逐帧输出。

## 参考与验证

参考用户提供的 KZ-Rush 1.12 `kz_jump_stats.sp`、`kz_demo.sp`、
`kz_jump_stats.cfg` 及附带说明。`.sp` 有反编译失真，不直接复制分支和地址常量。
原版源码和同输入游戏对照尚未取得，不宣称与服务器逐项完全一致。

`PlayModeJumpStats` 回归使用真实碰撞世界与移动命令，覆盖普通 LJ、无对岸的
HJ 失败、Hook 残余动量、辅助状态与传送/CP 中断、受阻与未支持技巧过滤、
指令量化与拆分，以及不同渲染刷新节奏下的结果和时间一致性。
