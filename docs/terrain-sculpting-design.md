# 地形雕刻与材质绘制方案

更新日期：2026-11-06  ·  状态：设计及实施中；本文中的目标不代表功能已经交付。

## 目标和范围

在当前 Half-Life / Valve 220 工程中，将地形作为一个可持续编辑的对象。作者可以创建地形、使用笔刷雕刻或调整顶点、绘制混合材质，然后反复修改形状和材质。保存和编译不应把编辑器中的地形变成需要逐个修改的 Brush。

高度场要求同一水平位置只有一个地形高度。悬挑、洞穴及上下重叠的地形使用其他地图几何。正常 Brush、项目资源和非地形地图功能不属于破坏性更新的范围。

## 操作流程

1. 从右侧地形面板选择创建方式：在 2D 俯视图框出新区域并设置高度、厚度；或选择现有地面 Brush / 组来创建。对不能准确转换的源几何给出明确原因，转换操作可撤销，不能静默改变或删除源数据。
2. 地形面板提供 **雕刻 / 顶点 / 材质** 三个平级模式，复用现有面板，不为每个模式增设主工具栏入口。笔刷状态、可编辑对象和不可编辑原因须明确显示。
3. 雕刻提供抬高、降低、平滑、压平，支持半径、强度和硬度；在 3D 中显示实际作用范围。顶点支持选择、框选和沿高度方向拖动，在 3D 与侧视图中可操作。
4. 材质使用已有的工程地形混合材质和槽位。切回雕刻或顶点模式后，已绘制的材质保持在地形局部坐标位置。工具模式切换不清空选择或撤销历史。
5. 一次笔画或拖动为一次撤销操作；Escape 取消进行中的操作。地形、所属组或图层锁定时不能修改，且应显示原因。
6. 正常保存后可继续编辑；工程保存及编译按需更新派生结果。编辑器预览、鼠标命中、选择范围和最终编译几何必须一致，不能用原有 Brush 遮挡或误命中新地形。

边缘默认应避免与相邻结构产生意外裂缝；对相邻地形块的共享边界，跨块雕刻与材质绘制须连续。不能悄悄覆盖其他地图结构。

## 实现约束

- 地形的形状与材质是编辑数据；编译 Brush、纹理与 WAD 是派生结果。若实现使用几何代理或缓存，必须从同一份地形数据更新，并在撤销、加载、变换、拾取和编译中保持一致。
- 原地面转换时检查覆盖范围、单值高度、底部与侧面及转换精度。对包含多个朝上面的合法源 Brush 应按实际表面处理；转换后的实体不能重复覆盖或产生空洞。
- 预览和编译使用一致的地形表面划分。编译时生成有效、封闭的凸 Brush，保留所需的地面及侧面语义，地形碰撞和视觉形状一致。
- 地形按块更新，修改影响到的网格和材质范围；相邻块共享或同步边缘。当前单区域 1280 × 640 单位的实现限制不能作为大地形的隐式截断，超出可处理或编译预算时必须清楚提示。
- 保留已有的混合材质、纹理复用、图集及四级 MIP 生成能力；可以调整不再适用的内部接口。估算面数和资源大小时区分估计值与实际编译结果。
- 选择、分组、复制、移动、锁定、可见性、撤销重做、工程保存重开都要对地形成立。显示或拾取用到的几何不能与编译输入成为相互独立的编辑真值。

## 格式与版本

本次可以破坏旧版**地形**数据兼容性，旧涂刷结果和旧地形区域不要求自动迁移。已有测试工程仅在副本中修改。用户选择现有 Brush 创建新地形是独立的建模功能，不等于要求支持所有历史地形数据。

- 工程容器版本、地形数据格式和地形编译缓存标识分别管理。地形格式只在数据语义或结构发生不兼容变化时升级；新增工具、界面、可带默认值的字段和普通修复不应触发升级。
- 不把应用版本、每次构建或每个提交当作地形格式版本。避免为增加功能反复引入新的地形格式分支或无必要的迁移。
- 旧程序如果能够打开工程却会误改新地形，应通过工程的最低读取版本或现有容器版本保护，在首次不兼容的发布中统一处理。具体方案须验证旧版实际行为，不能假设旧版认识新增字段。
- 编译缓存是可丢弃的派生数据，单独以生成器身份、地图修订、材质依赖与相关参数判断是否失效。生成结果语义发生变化时必须重算；不能为了让格式版本稳定而继续使用过期缓存。无关的界面改动和构建不应导致缓存失效。

### 当前实现约定

- 保留现有材质区域数据；带高度场的区域使用地形格式 `5`，主体为 URL 安全 Base64 编码的 JSON，避免地图属性分片截断引号或转义符。`origin` 是局部左上角，`weights` 保存原有三槽权重，预算与材质绑定沿用现有含义；`heightField` 保存列数、行数、网格间距、统一底面和行优先高度值。格式 `1–4` 的已有读取不受此影响。
- 同一网格中的 X 向右递增、Y 向下递增，每个网格固定沿左上至右下对角线划为两个三角形；采样和凸 Brush 生成使用同一划分。当前单区域材质覆盖仍为 1280 × 640 地图单位，后续大地形由分块方案处理。
- 每个三角形生成一个闭合凸 Brush。编译前逐个核对代理 Brush 的顶点、底面、网格位置与三角形归属；如果形状被外部顶点工具改动而与高度场不一致，返回错误，不能静默编译。相邻源 Brush 转换前检查覆盖、底面、边界对齐及共享边界高度。
- 未知的可选 JSON 字段在读写时保留；需要改变既有字段语义时再升级地形格式。本次多顶面切割修复改变了生成结果，因此仅将独立的地形编译缓存生成器标识从 6 更新到 7，并不改变工程容器版本。

## 实施与验收

实施顺序：建立地形编辑与版本边界；接通两种创建方式和三种编辑模式；接通保存、预览、拾取和编译；最后完善分块、预算提示和性能。每个阶段应保持可构建，完整功能须作为端到端流程验收。

当前进度：已实现高度网格、四种雕刻运算、凸 Brush 生成、数据序列化和代理几何一致性校验，并支持多顶面的现有地形编译。已有可撤销的内部地面转换操作，保留源 Brush 的外表面材质和 UV；坡面采样目前接受连续的矩形平面 Brush，要求底部平坦、边界与网格对齐且接缝高度一致。关联组的地形数据同步尚未实现，转换时会明确拒绝。雕刻交互、顶点编辑、两种创建入口、跨块编辑及完整验收仍未完成；现有面板尚不能使用新雕刻功能。

新的可雕刻地形使用一个可扩展的数据格式：可选的未知字段在读写时保留，字段语义不兼容时才需要调整格式版本。缓存生成器标识独立管理，不能用它代替地形格式版本。

自动验证覆盖：地形采样和边界、雕刻及材质互不丢失、笔画取消和撤销、保存重开、格式识别、缓存失效、复制与变换、多顶面源几何、跨块边缘和生成 Brush 的覆盖与有效性。

人工验收使用 `terrain-slope.tbproj` 的副本及新建地图：实际操作创建、雕刻、顶点调整、材质涂刷、二次雕刻、保存和重开；检查 2D / 3D 拾取与显示。使用工程编译和 `hltools` 验证实际 BSP 和纹理；具备运行环境时进入游戏检查碰撞、封闭和视觉接缝。检查较大地形、实时交互、编译面数与纹理大小，记录实测而非推算为已验证结果。

UI 使用项目统一控件和样式；完成后更新双语离线手册，并按项目规则执行相关测试、Release 构建和 UI 风格检查。
