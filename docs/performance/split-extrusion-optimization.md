# 分割挤出：复用预览节点

测量日期：2026-09-08。基于 `46a74bc41` 实现的本次优化，使用与[原始定位](split-extrusion.md)相同的 Windows Release、Qt 6.11.1、正式 Dark 主题和完整 MapWindow 测量。

## 结果

稳定分割拖动改为复用节点、批量交换内容，单 brush 向外分割平均工作时间从 **12.740 ms 降到 1.058 ms（减少 91.7%）**。含 64 个 brush、仍只拖一个面时，从 **24.261 ms 降到 1.309 ms（减少 94.6%）**。同轮普通 Shift 挤出分别为 1.516 和 1.859 ms，原先的数量级差距已消除。

单位：ms/有效拖动更新，包含 picking、控制器更新、同步通知、Qt 事件处理及一次正常视口绘制。

| 地图 brush 数 | 模式 | 优化前平均 | 优化后平均 | 后中位数 | 前 P95 | 后 P95 | 平均耗时减少 |
|---:|---|---:|---:|---:|---:|---:|---:|
| 1 | 普通 | 1.953 | 1.516 | 1.220 | 4.210 | 3.173 | 对照 |
| 1 | 向外分割 | 12.740 | 1.058 | 0.921 | 29.061 | 1.869 | 91.7% |
| 1 | 向内分割 | 10.770 | 1.274 | 1.123 | 16.431 | 2.177 | 88.2% |
| 64 | 普通 | 1.713 | 1.859 | 1.584 | 3.104 | 3.607 | 对照 |
| 64 | 向外分割 | 24.261 | 1.309 | 1.059 | 50.919 | 2.528 | 94.6% |
| 64 | 向内分割 | 24.798 | 1.447 | 1.225 | 51.170 | 2.712 | 94.2% |

普通模式未改动，跨轮耗时变化反映系统调度等波动。优化后的分割比同轮普通略快，与每步仅一次内容交换、无回滚相符；不应将此推广为所有地图的固定倍率。这里是完整窗口基准的工作时间，未测量真实 OS 鼠标事件采集或屏幕呈现 FPS。

## 修改及行为

[ExtrudeTool.cpp](../../lib/TbAppLib/src/ExtrudeTool.cpp) 的 inward/outward 路径先从拖动起点的 brush 快照计算所有新几何，再交给 `applySplitBrushes` 更新预览。[ExtrudeDragState](../../lib/TbAppLib/include/ui/ExtrudeTool.h) 记录与初始 handle 顺序对应的预览节点；完全裁掉的部分记录为空。

- 方向和存活分割块集合不变时，复用现有节点。向外只交换新增块的内容；向内一次批量交换原节点的 front 和预览节点的 back。重新查找拖动面的索引，适应 clip 改变 face 排列。
- 方向变化或某个分割块消失/恢复时，回滚当前拖动事务并构建新拓扑。回到零位移则恢复原始几何和选择。
- 所有几何计算完成后才修改地图。非法几何保留上次有效预览并返回拖动拒绝；若拓扑替换因关联组更新失败而已经回滚，尝试恢复上次有效位置。
- 沿用原生 `updateNodeContents`、关联组传播及拖动长事务。连续内容交换通过现有 `SwapNodeContentsCommand` / `TransactionCommand` 合并，撤销、重做、取消不会逐步遍历整个拖动历史。

节点新增、删除、内容及选择仍通过正式地图接口通知所有观察者。Outliner、属性编辑器和 renderer 自身逻辑无需改变。相同方向的稳定预览保持 identity、link ID、父节点和选区，因而不再产生引发树和属性行重建的事件。

## 每步工作消除了什么

完整窗口、单 brush 向外分割的调用数；数值均为每次有效稳定更新：

| 阶段 | 优化前 | 优化后 |
|---|---:|---:|
| 事务 rollback | 1 | 0 |
| 节点新增 / 移除 | 1 / 1 | 0 / 0 |
| 选区通知 | 4 | 0 |
| 内容交换 `doSwapNodeContents` | 0 | 1 |
| Outliner 子树刷新 / 选区同步 | 2 / 6 | 0 / 0 |
| Outliner 属性行重建 | 1 | 0 |
| 所有视图接收者的 repick | 24 | 4 |
| QWidget Paint 投递 | 19 | 1 |
| 视口绘制 | 1 | 1 |

向内分割同样没有稳定更新期间的增删、选区通知或回滚，一次内容交换同时更新两个 brush。其几何仍包括 front/back 复制和两次 clip。

64 brush 场景的向外 `BrushRenderer::validateBrush` 从每步 65 次降到 1 次；向内更新两个选中 brush。稳定节点和选区还消除了 default renderer 在增删时对 readable 2D outlines 的全体失效。

## 复现与范围

```powershell
python scripts/profile-extrude.py run --repeat 3 --brushes 1 64 --output build-release-codex/codex-logs/extrude-profile/optimized
```

探针补丁已适配新实现；脚本结束时反向恢复探针并重建普通 `TbUiLibTest`。原始数据在上述输出目录。仓库保存[全部环境统计](split-extrusion-optimized-results.csv)和[完整窗口探针统计](split-extrusion-optimized-scopes.csv)，原始优化前 CSV 保留不覆盖。

与定位阶段相同，5 种环境 × 2 种地图大小 × 3 轮，30 个独立实验进程，90 组数据、共 10,800 个计时样本。每组 20 次预热、120 次计时，走实际 `ExtrudeToolController3D` 和拖动 tracker。所有样本通过位移断言、结束取消后的节点数和初始边界断言。exclusive 总和核对通过，完整窗口每样本仍绘制一次视口。

正式改善值取 `baseline` 环境，即完整 UI。原诊断中的旁路环境保留用于复现；优化后对应函数本来就不再调用，旁路场景间的细小时间差不代表额外收益。

这些数据覆盖单面持续同方向拖动。首次创建预览、换向及分割块消失/恢复仍走拓扑重建路径，其低频成本未计入稳定更新均值。复杂地图资产、斜面及大量同时选中 brush 的耗时需要按实际地图另测。

## 撤销边界

2026-09-09 补充修复：命令处理器在创建已提交的事务命令时保留 `TransactionScope`，禁止 `LongRunning` 事务与前后事务合并。一次鼠标拖动因此保留独立的撤销步，内部 `Oneshot` 预览事务仍可合并。修复前，分割挤出后在默认 1 秒合并窗口内完成移动拖动，一次撤销会连同分割一起撤销。

回归测试显式启用正式编辑器的跨事务合并配置，覆盖向内/向外分割后立即移动、分别撤销和重做两个操作；连续 100 步的节点、选区及通知计数和有界撤销检查也使用该配置。命令处理器测试同时验证长事务两侧的边界、内部预览合并，以及原有短事务合并。几何计算和每帧节点更新链路没有修改，前述性能数据来自原优化复测。

该修复通过 `CommandProcessor` 的 367 个断言、`ExtrudeTool*` 的 3,162 个断言及 Release `TrenchBroom` 构建。`ci-preflight.ps1 -BaseRef HEAD` 通过 3 个修改单元的严格编译，以及 TbAppLib 47、TbMdlLib 135、模型测试辅助库 5 个 CTest 用例（共 187 个）。
