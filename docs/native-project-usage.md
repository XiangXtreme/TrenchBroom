# TB 工程试用说明

当前实现包含 `.tbproj` 工程、独立资产库、工程资源快照与编译快照导出。传统独立
MAP 编辑仍可使用。

## 创建与打开

1. 在欢迎页选择 **New Project…**，或在地图窗口选择 **File → New Project…**。
2. 选择游戏及地图格式，保存 `.tbproj`。首验目标为 Counter-Strike 1.6 对应的游戏配置。
3. 工程窗口管理内容与版本，地图在窗口内的标签中编辑；切换标签保留各自的编辑状态。
4. **Project → New Map…** 创建其他地图；**Import Files…** 导入已有内容。
5. 双击工程内容列表或 Asset Browser 中的地图，打开或切换其编辑标签。
   原有打开文件入口也支持 `.tbproj`。

## 地图预览

保存工程时，会从当前可见的三维地图视角生成预览，隐藏网格、选择标记和操作工具。
预览以 PNG 存入 `.tbproj`，关闭地图后仍能在“当前工程”的地图卡片中查看，浏览时
无需加载地图。未打开或没有可见三维视图的地图保留上次预览。

地图卡片右键 **使用当前视角更新预览** 可手动更新；先打开该地图的三维视图，
调整到合适角度，再执行此操作并保存工程。没有预览的地图显示 MAP 占位。预览是
独立的派生缓存，更新它不会增加地图内容修订。

## 资产库

资产库是一个普通文件夹，内含隐藏目录文件 `.tbassets`。库不是工程，可以同时被
多个工程引用，也可以整体移动。`.tbproj` 不再保存自己的库关联：库路径是应用级设置，
所有工程共用同一个库。

1. 欢迎页 **Asset library…** 打开库浏览器，选择文件夹并确认“建立资产库”后会生成
   目录文件。工程窗口没有 Attach / Relink 入口。
2. **Import Files…** 选择 WAD、PNG/BMP/TGA、MDL、SPR、WAV 等，将原始内容与转换结果
   直接存入 `.tbassets` 数据库；导入完成后可移动或删除原文件。模型的外置纹理和动画组
   在导入时一并收进库内，不再持续跟踪来源目录。
   同名资源一次性询问 **覆盖 / 保留两者（自动加后缀）/ 跳过**。
   库浏览器支持 ☆ 收藏、**Rename…** 和 **Delete…**；支持多选、`Ctrl+A` 全选和
   `Delete` 批量移除。左侧分类可双击或按 F2 改名，名称与层级保存在数据库中，
   不改动引擎虚拟路径、资源 ID 或模型依赖。顶层资源类型用于筛选。
   工程已经捕获的副本不会受影响，重新导入可以恢复库条目。
   检查器的 **Used by** 会列出最近打开过的工程中捕获了该资源的项目，打不开的工程会被
   跳过，不影响浏览。
3. 导入时立即转换：图片会转成 GoldSrc 纹理内容（256 色 + 四级 mip，`{` 前缀表示
   二值透明），原图仍留在库里，State 列显示 **Converted**，预览显示的就是转换后效果。
   纹理名在导入时按文件名规范化（大写、非法字符转 `_`、截断 15 字符），需要时可再改。
4. 库只在显式导入或替换时接收新内容；打开、刷新或检查工程更新只读取库内数据库。
   直接修改或添加磁盘文件不会影响库内内容。建立新库时会一次性导入所选文件夹中的资源。
5. 工程里捕获过的资源如果和库当前内容不一致，内容浏览器与资源列表会显示
   “New library version available” 角标；点按 **Use Current Library Version** 才会更新，
   不会自动改写工程。

库中的 WAD 容器显示为一个分组，每个纹理条目是独立资源，拥有自己的稳定 ID、
内容哈希与修订号。模型会记录 `<name>T.mdl` 外置纹理模型和声明的外部动画组，
六面齐全的天空盒会形成一个组资源并依赖六张面。只有库中确实保存的资源才会成为
依赖。

## 浏览与绑定

工程窗口底部只有一条工具栏：**内容浏览器 / 输出日志 / Python 控制台 / 问题 / 扩展**。
内容浏览器管理工程和资产库来源；资源列表和版本历史也放在同一面板里。游戏目录文件
只在单独打开 MAP 时显示；要在工程中使用它们，需要先导入工程或从资产库捕获。
日志、Python 控制台和问题跟随当前地图，切换地图保留各自的内容；关闭全部地图后
仍能浏览工程资源，地图相关工具暂时禁用。“扩展”打开当前地图原有的插件检查器。

点击底栏入口展开临时抽屉，再次点击或按 Esc 收起；回到地图编辑时自动收起。
**固定停靠**让工具面板占据布局空间并保持展开，可拖动分隔条调整高度；取消固定后
恢复临时抽屉。编辑器记住固定状态。**Ctrl+Shift+Space** 展开或收起上次使用的工具页
（内容浏览器、输出日志、Python 控制台或问题），原来的
Ctrl+Space 继续用于最大化视图和 Python 补全。

顶部的“资产库｜当前工程”双段切换始终显示两个选项，单击即可切换，默认打开资产库。资产库只显示库内资源，
沿用库内自定义分类；已捕获到工程的资源带有工程标记。“当前工程”只显示工程保存的
资源快照，根目录显示工程名，也包括尚未放入地图的资源。“当前地图使用”筛选仅在
工程模式中提供。两种模式分别记住目录、搜索和滚动位置。

在“当前工程”的 **筛选 → 无地图引用** 中，可列出所有工程地图均未使用的资产
（不包含地图本身）。检查包含已关闭地图、打开地图的未保存修改，以及资源的间接
依赖。地图扫描失败时显示“引用扫描失败”，不会将无法确认的资产归入无引用结果。

资产卡片右键 **从工程移除…** 可删除工程副本；确认后会重新检查引用，有地图引用
时列出地图并阻止移除。仍被其他工程资产依赖的资源也不能单独删除。资产库原件
保留，保存工程后移除结果持久化；历史版本占用的空间仍由版本清理功能管理。

- 选中资产库时，浏览的是库的当前内容。内容浏览器中双击纹理会应用到已选的面，
  双击天空盒会设置当前地图的天空；库资源会先捕获进工程。没有选中面时，双击纹理
  不产生修改。模型、Sprite、声音等资源双击打开只读预览。
  右键 **Add to Project** 可显式复制当前修订。
- 模型、Sprite、声音可直接从库拖入工程地图：拖入只创建临时放置预览，松开后才把
  所选修订及依赖捕获进工程；取消不捕获。载荷使用资源 ID 与修订，跨工程或过期
  载荷会被拒绝。
- 纹理拖入地图会捕获所选修订，并把鼠标下的面（没有命中时用已选的面）的材质改成该
  纹理名；同一次拖放只产生一步原生撤销。一个工程 WAD 里嵌入多张纹理时没有唯一名字，
  拖放会拒绝并提示先拆分。
- 天空盒在顶层 `skybox` 目录中按组显示，每组一张缩略图，六面图片由组统一管理。
  双击或拖入地图会一次性捕获组和六个面，并把 worldspawn 的 `skyname` 设成该组的
  基名；应用纹理或天空盒都支持原生撤销和重做。撤销地图修改会保留已捕获的工程资源。
  编译发布时六面统一缩放为标准 GoldSrc 使用的 256×256、24 位无压缩 TGA；工程中
  保留原始图片。六面源图必须是不透明、同尺寸的正方形。
- 已经绑定的库资源会同时显示工程修订号、发布路径与更新状态；工程来源的拖放
  使用已捕获修订及其发布路径，库来源使用本次选中的库修订。
- 若库资源的发布名与工程里已有资源相同，应用、拖放或 Add to Project 会先询问是否替换；
  替换沿用原资源 ID，地图引用继续有效，被替换的修订保留在工程历史里。
- 切换内容来源时，模型、纹理、Sprite、声音预览随来源与修订更新。库预览读取库当前修订，工程来源仍使用
  已捕获快照；预览生成或解码失败时，将鼠标停在资源上可查看失败提示。
- 右键 **Use Current Library Version** 显式刷新快照，**Find Uses in Project**
  列出该资源在工程地图中的使用位置。

解绑后库文件消失或损坏都不影响工程：工程保存的是内容快照，地图、预览、编译都不
再需要原库。

## 更新与忽略

工程窗口没有库菜单，也不再有批量更新对话框：库是全局的，变更在内容浏览器里逐个
处理——右键 **Use Current Library Version** 把该资源更新到库的当前内容，其它资源
不受影响。

- 勾选后 **Update Selected** 一次性更新所选资源；更新在单个存储事务内完成，
  任何一个失败则全部保持旧修订。资源沿用原 ID，所有地图引用同时生效，旧修订仍可
  在历史中恢复。
- 纹理更新保留工程当前的 miptex 名称，包括通过发布路径重命名设置的名称。即使库里重新
  转换时用了另一个纹理名，工程地图仍沿用原来的引用；像素、尺寸和库修订按新版本更新。
- **Ignore This Version** 只忽略当前库版本，之后库再次变化仍会提醒。
- **Remind Me Later** 只对当前会话生效，下次打开工程会重新提示。
- 缺库、资源被删除或不可读只影响状态显示，不会自动修改工程。库目录被移动后，用
  欢迎页的 **Asset library…** 重新指向新位置即可；已捕获的快照不受影响。
- 只改了依赖、内容没变时也会提示（“库中的依赖已变化”）：例如库为某个模型新增了
  配套文件。更新会补捕获这些依赖并重写依赖图，主体内容修订保持不变。

库出现新版本不会自动改写任何工程；同一资源在不同库中同名但内容不同时直接报冲突，
需要手动处理。

## 导入与使用内容

支持 MAP、MDL、SPR、WAV、TBPREFAB、WAD 和 PNG/BMP/TGA/JPG 图片。
内嵌内容随工程保存，不依赖导入原文件继续存在。

GoldSrc 图片导入时指定纹理名，预览自动缩放、减色及透明处理，再确认导入。
转换结果为包含四级 mip 的 256 色 WAD3 纹理；尺寸限制为 512 以内的 16 倍数。
`{` 前缀启用二值透明，alpha 阈值为 128。工程同时保留原图和转换参数。
导入的 WAD 与转换后的纹理自动用于工程地图，可在面检查器中选用。
主 Asset Browser 当前显示 WAD 的首张可解码纹理作为预览，尚不支持拖放 WAD 卡片贴图。

从资产库捕获的模型会自动带上分离纹理文件（`xxxT.mdl`）和外置动画组
（`xxx01.mdl` 等）；GoldSrc 模型的内嵌纹理本来就在模型里，不会额外捕获同名图片。
模型及天空盒的依赖按完整库内路径匹配，不会连接其他目录中的同名文件。
捕获天空盒会带上六面。整个闭包在一个事务里提交，任何一个依赖失败都不会留下半成品。
直接导入原生模型、Sprite、声音与预制件按原文件保存；Sprite 帧、WAV 引用等仍需
自行补齐，不能据此认定工程已收集地图的全部依赖。其他类型也不会仅因导入成功就
标记为“引擎验证通过”。

**Asset → Reimport…** 替换所选内容并保留身份；工程内引用使用同一游戏路径，
已打开地图与预览会刷新。外部原文件的修改不会自动覆盖工程内容。
**Rename…** 改显示名称，**Move…** 改虚拟路径；两者均保留首次导入的游戏路径。
**Rename Published Path…** 改引擎使用的地图引用名：命令先写一个安全版本，再把工程内所有
**已关闭**地图里的对应引用改写成新名字，最后更新资源的发布路径。模型/Sprite/声音改写实体
里的游戏路径；纹理必须是单纹理 WAD，会把 miptex 改名并重写面材质与补丁。路径已被占用、
地图仍在打开或多纹理 WAD 时会拒绝并保持原样。
库内分类名称和文件夹与游戏发布路径分别管理。模型、Sprite 和声音的新导入路径
使用工程设置中的资源前缀，其他类型沿用各自的引擎目录。

地图里已经写了引用、但还没嵌入工程的资源，可用 **Project → Capture Map Resources…** 从已
关联的库补捕获：面材质按引擎纹理名匹配，实体的 `model`、`message`、`shootmodel` 等按游戏
路径的完整目录后缀匹配，并保留地图要求的发布路径。多个候选不会按库顺序自动选择，
而是和缺失引用一起列在提示中；可手动捕获目标资源后调整发布路径。手动捕获模型、Sprite
与声音会保留库内目录结构，例如资源前缀为 `kz` 时，`nature/trees/bush.mdl` 发布到
`models/kz/nature/trees/bush.mdl`。SPR/WAV 是单文件格式，本身没有
可枚举的外部依赖。

## 工程设置与资源发布

**Project → Project Settings…（工程 → 工程设置）** 配置资源前缀与游戏 / 模组目录。
新工程默认从工程名生成前缀；旧工程打开时沿用原发布路径。前缀可留空，或使用最多
32 个 ASCII 字母、数字、下划线和连字符。模型与 Sprite 的完整发布路径最多 63 字节。
例如前缀 `kz_climb` 对应 `models/kz_climb/crate.mdl`、
`sprites/kz_climb/glow.spr` 和 `sound/kz_climb/wind.wav`。
天空盒六面直接发布为 `gfx/env/<skyname>{bk,dn,ft,lf,rt,up}.tga`。

目标目录选择游戏的模组根目录，例如 `cstrike`，留空则关闭自动发布。真实编译开始前，
编辑器将当前地图实际使用的模型、Sprite、声音、天空盒及已捕获的配套文件发布到这里。
同路径同内容文件可复用；同路径不同内容时，在复制任何文件之前停止并报告冲突。
试运行不写入目标目录。此设置负责依赖资源，BSP 的输出或复制仍由编译配置决定。

只改前缀时，已有资源和地图引用保持原样，新资源使用新前缀。勾选“迁移已有资源路径
及地图引用”可查看旧路径与新路径，再应用到工程。迁移会先创建包含未保存地图编辑的
安全版本，成功后重新加载打开的地图并清空它们的撤销历史；失败时保留当前工程。
迁移仅替换当前配置的前缀；若此前曾只改设置而未迁移，旧前缀可能保留在子目录中，
请以预览结果为准。应用后仍需保存工程。

资产库的模型、纹理、声音等类型分区保留，可在文件夹树中双击或按 F2 自行命名，
并在分区下管理子文件夹。配置名称按原文显示，不随界面语言翻译；内部类型、游戏目录
和模型依赖不会因为分类改名而变化。

## 编译快照

**内置编译（GoldSrc）**：打开工程中的地图，在编译对话框点击 **内置 hltools** 创建配置，
选择输出路径、光照质量、GPU 和附加参数即可编译，无需安装外部 hltools。
默认 BSP 和日志保存在 `.tbproj` 旁的 `compiled` 目录。输入使用本轮冻结的地图与资源快照，
支持工程捕获的纹理、模型等依赖和地形编译结果；关闭对话框不会删除默认输出。
资源检查与发布设置继续生效。停止或编译失败会保留上次的 BSP，并停止后续任务。
可追加 **Copy Files** 任务部署 `${BSP_PATH}`，再追加 **Launch Engine** 在编译成功后运行游戏。
单独 MAP 也可使用同一任务，默认输出为源 MAP 旁的 `compiled` 目录。

直接工程编译与快照导出都会先检查当前地图的资源引用；缺失、歧义、非法路径和扫描失败
会阻止启动工具。编译器工具纹理、编辑器空材质和游戏自带天空仍允许作为外部资源。
此检查不代表游戏内完整流程验收。

工程地图现在有两条编译输入：

1. **直接读工程（推荐）**：编译前 TB 会先保存工程，profile 里可以用
   `${PROJECT_PATH}` 和 `${MAP_NAME}`：

   ```text
   hltools compile --project "${PROJECT_PATH}" --map "${MAP_NAME}" --output "<输出>.bsp"
   ```

   hltools 以只读方式打开 `.tbproj`，取出这张地图和工程里已转换的纹理，临时展开后
   直接编译；贴图嵌进 BSP，不产出 WAD，也不需要快照目录。编译日志落在临时目录，
   BSP 写到 `--output`（默认放在工程旁边）。
2. **固定快照目录**：仍可用于旧 profile 或外部工具，内容为：

- `map.map`：当前地图内容。
- `textures.wad`：只含该地图按名字实际引用、已转换为 GoldSrc 兼容格式的纹理。
  导入的整包 WAD 也只导出被用到的那几张。
- `wads.cfg`：供 hltools `-wadcfgfile` 使用的 WAD 列表。
- `snapshot.txt`：工程 ID、地图修订、每个资源的 ID/修订/内容哈希、`direct`/
  `dependency` 标记、纹理清单，以及 `external`（编译器工具纹理与未捕获的天空盒面）。
- `resources/<发布路径>`：被引用的模型/Sprite/声音及其工程依赖闭包。
- `resources/gfx/env/<天空盒名><面后缀>.tga`：已捕获天空盒的六面。从工程保存的
  图片原件生成不压缩 24 位 TGA，保留 RGB 和方向；六面必须是不透明、同尺寸的正方形。
  缺面、重复面、歧义或无法解析会阻止导出。清单记录面资源修订、来源哈希和 TGA 哈希。
  发布时将 `resources/` 下的目录结构复制到游戏或 mod 目录；天空盒不写入 WAD/BSP。
  更新资产库只影响显式更新后的新快照，移走原资产库不影响已捕获天空盒的导出。

如果引用的纹理缺失、歧义、路径非法或地图无法扫描，导出会**直接失败**并指出具体
引用、地图与行号，不会生成一个贴图不全的 BSP。捕获这些资源后再导出即可。

快照目录可以独立运行，不需要资产库，也不需要打开 TB：

```powershell
cd <snapshot>
hltools compile -wadcfgfile wads.cfg map.map
```

hltools 默认把地图用到的纹理嵌入 BSP，未使用的资源不会进入 BSP；`bsp info`
会显示嵌入纹理数。vis 阶段需要 `.prt`，与快照无关。

包含已涂刷地形的工程保存时会自动记录与地图修订对应的地形编译结果；工程内编译和
新版 hltools 的 `--project` 直接编译都会使用它，无需手工导出 WAD。生成失败或结果
过期时会报告原因。旧工程首次用新版 TB 保存后即可由新版 hltools 直接编译；包含该
结果的工程为格式版本 4，需使用支持此版本的 TB 和 hltools。

**从工程窗口编译**时不需要手工导出：仅包含一个启用的工具任务、参数使用
`${PROJECT_PATH}` 且不引用地图路径变量的配置直接读取已保存的工程。包含其他启用任务
或地图路径变量的配置会先导出一份新的快照到独立目录，并把 `${MAP_DIR_PATH}`、
`${MAP_FULL_NAME}`、`${MAP_BASE_NAME}` 指向这份快照。
地图文件沿用工程里的名字（例如 `alpha.map`，而不是 `map.map`），所以按 `${MAP_BASE_NAME}`
派生输出名的现有配置不用改。编译进程的工作目录也解析到快照里，配置中的相对路径
（例如 `-wadcfgfile wads.cfg`）同样落在快照目录。快照在这一轮运行期间不会被编辑、
切换标签或库更新改写。配置中的 **Export Map** 任务也读取同一份冻结地图，
同时保留属性过滤、实体过滤和添加实体等导出选项；再次运行才会捕获后续编辑。

快照目录是一次性的：外部工具若把编译产物写在里面，对话框关闭后随之删除，因此发布流程仍应像普通
TrenchBroom 一样用复制任务把 `.bsp` 拷到游戏或 mod 目录。需要长期保留的输入请用
**File → Export Compile Snapshot…** 显式导出。

如需沿用手动发布流程，可在编译配置末尾添加一个 **Copy Files** 任务：Source 填
`${MAP_DIR_PATH}/resources`，Target 填游戏或 mod 根目录（例如 `cstrike`）。
目录来源会把内容按原层级复制到目标，包含 `models/`、`sprites/`、`sound/` 和 `gfx/env/`，
不额外套一层 `resources/`；已有同名文件会覆盖。`.bsp` 仍单独复制到游戏的 `maps/`。
文件名通配符仍只匹配来源目录的一层文件。试运行只显示计划，不写入目标目录。
该手动复制任务具有覆盖行为；已配置工程自动发布时，无需再添加资源复制任务。

## 保存与版本

- 地图窗口的 **Save / Ctrl+S** 与工程窗口 **Save Project** 都保存整个工程，包含
  其他已打开地图的修改。标题中的修改标志反映工程状态。
- **Save Project Copy…** 输出当前完整副本，不切换当前工程，也不清除当前修改标志。
- 工程资源的导出副本用于取出兼容结果；独立 MAP 使用地图窗口的导出功能。
- 关闭地图时可保存整个工程或丢弃该地图尚未保存的编辑。关闭工程前先关闭地图，
  工程本身还有修改时会再次询问保存。
- **History → Create Version…** 建立命名节点，包含当前未保存的地图内容。
  随后保存工程才能将该节点持久写回原文件。
- 选择版本后可比较当前状态，查看发生变化的资源/地图与依赖数量。
  这还不是几何或图片的可视化差异查看器。
- 地图保持打开时也可恢复版本。恢复前自动将当前状态（含未保存地图编辑）存入安全版本，
  然后重新加载所有打开的地图并清除地图脏标记；恢复结果仍需保存工程。
  若版本不包含某张打开的地图，需先关闭该地图的编辑会话再恢复。
  恢复会先准备独立工程副本和全部地图；缓存写入或地图解析失败时，当前内容、
  脏标记、撤销历史和工程依赖保持原状，不会只恢复部分地图。

同一工程使用锁防止被两个会话同时编辑；保存还会检查原文件是否被外部改动。
冲突时保留当前工作状态，改用保存副本，不覆盖外部版本。
