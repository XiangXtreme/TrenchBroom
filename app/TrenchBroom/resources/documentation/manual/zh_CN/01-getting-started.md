# 入门 {#getting_started}

本节首先简要介绍基于 Brush 的引擎制图相关的重要技术术语，并介绍 TrenchBroom 构建于其上的一些概念。随后将介绍欢迎窗口和游戏选择对话框，概览主窗口，并说明如何在 3D 和 2D 视图中操控摄像机。

## 准备知识 {#preliminaries}

本节介绍 Quake 引擎类游戏制图相关的技术术语。你不必理解所有细节，但应大致了解地图的结构，以及 TrenchBroom 如何查看和管理这些结构，才能理解它的工作方式。本节还会介绍我们加入地图结构的概念（当然不会改变文件格式）。掌握这些概念有助于理解在 TrenchBroom 中编辑关卡的重要方面。

### 地图定义 {#map-definitions}

在 Quake 引擎类游戏中，关卡通常称为地图。下面使用扩展巴科斯-诺尔范式（EBNF）描述地图结构。EBNF 是计算机科学中广泛用于定义计算机语言语法的一种简单层次结构语法。不必担心看不懂 EBNF，我们会逐行解释这些定义。

    1. `Map      = Entity {Entity}`
    2. `Entity   = {Property} {Brush}`
    3. `Property = Key Value`
    4. `Brush    = {Face}`
    5. `Face     = Plane Texture Offset Scale Rotation ...`

第一行说明一个**地图（map）**包含一个实体，其后跟随零个或多个实体。在 EBNF 中，包裹单词“Entity”的大括号表示它代表一个可能为空的实体序列。总的来说，第一行意味着地图就是由一个或多个实体组成的序列。一个**实体（entity）**是一个可能为空的属性序列，其后跟随零个或多个 Brush。一个**属性（property）**就是一个键值对，键和值都是字符串（EBNF 中省略了这一信息）。

第四行将 **Brush** 定义为一个可能为空的面序列（但通常至少有四个面，否则 Brush 将无效）。而在第五行中，我们最终定义了一个**面（Face）**具有一个平面、一种材质、X 和 Y 偏移量与缩放比例、旋转角度，以及可能根据游戏而定的其他属性。

本文使用 _object_（对象）一词指代实体和 Brush。

### TrenchBroom 对地图的视图 {#trenchbrooms-view-of-maps}

TrenchBroom 组织地图对象的方式与它们在地图文件中的组织方式略有不同。首先，TrenchBroom 引入了两个附加概念：[图层](#layers)与[组](#groups)。其次，worldspawn 实体对用户隐藏，其属性直接关联到地图上。为了将 TrenchBroom 的视角与其他工具和编译器的视角区分开来，我们在此使用术语“world（世界）”代替“map（地图）”。在本文档的其余部分中，我们将重新使用术语“地图”。

    1. `World        = {Property} DefaultLayer {Layer}`
    2. `DefaultLayer = Layer`
    3. `Layer        = Name {Group} {Entity} {Brush}`
    4. `Group        = Name {Group} {Entity} {Brush}`

第一行定义了 TrenchBroom 视角下的地图结构。对 TrenchBroom 而言，一个 **World** 由零个或多个属性、一个默认图层以及零个或多个附加图层组成。第二行指定 **DefaultLayer** 本身就是一个图层。接着，第三行定义了什么是**图层（Layer）**：图层具有一个名称（字符串），并且包含零个或多个组、零个或多个实体以及零个或多个 Brush。在 TrenchBroom 中，图层用于将地图划分为几个大区域，以便通过隐藏它们来减少视觉混乱。相比之下，组用于将少量对象合并为一个对象，以便作为一个整体进行编辑。与图层类似，**组（Group）**由一个名称、零个或多个组、零个或多个实体以及零个或多个 Brush 组成。你可能已经注意到，组构成了一个层次结构，也就是说，一个组可以包含其他子组。所有其他定义均与上一节完全相同。

总而言之，TrenchBroom 将地图视为一个层次结构（树状结构）。层次结构的根称为 world（世界），代表整张地图。世界首先由图层组成，然后是组、实体和 Brush；其中组可以包含更多的组、实体和 Brush，实体又可以包含 Brush。由于组可以包含其他组，因此该层次结构可以具有任意深度，尽管在实践中组很少包含超过一层的子组。

### Brush 几何 {#brush_geometry}

在标准地图文件中，Brush 的几何体由一组面定义。除了定义 UV 映射的属性之外，面还使用三个平面点来指定一个平面。平面的朝向由地图文件中面规格中这三个点的书写顺序决定。示例如下：

    ( 32 32 -3824  ) ( -32 32 -3824  ) ( -32 96 -3824 ) mmetal1_2 0 0 0 1 1

平面点以三组数字的形式给出，每组由三个数字组成，分别指定对应平面点的 X、Y 和 Z 坐标。三个点 p1、p2 和 p3 定义了两个向量 v1 和 v2，如下所示：

      *p2
     /|\
      |
      v2
      |
    p1*--v1--->*p3

平面的法线方向是 v1 和 v2 的叉积方向。在上面的示意图中，平面法线指向屏幕外的你。平面与其法线一起将三维空间划分为两个半空间：平面上方的上半空间和平面下方的下半空间。在这种解释下，Brush 的体积是所有面的平面所定义的下半空间的交集。这种定义 Brush 的方式具有所有 Brush 都自动保持凸多面体（convex）的优点。然而，Brush 的这种表示方式并不直接包含 Brush 的任何其他几何信息，特别是它的顶点、边和多边形面片（facet），这些必须从平面表示中计算得出。在 TrenchBroom 中，顶点、边和面片统称为 **Brush 几何（brush geometry）**。TrenchBroom 使用与 BSP 编译器相同的方法来计算 Brush 几何。拥有 Brush 几何主要用于两件事：渲染和顶点编辑。

### 实体定义 {#entity_definitions}

对 TrenchBroom 而言，实体只是一系列属性（键值对），其中大多数没有任何特殊含义。特别是，实体属性并没有指定 TrenchBroom 应该在视图中为该实体显示哪个模型。此外，某些属性值具有特定类型，例如颜色、角度或位置。但这些类型无法硬编码到编辑器中，因为根据游戏、Mod 或实体的不同，名为“angle”的属性可能具有不同的含义。为了向 TrenchBroom 提供有关如何解释特定实体及其属性的更多信息，实体定义是必不可少的。实体定义指定了实体的 spawnflags、其属性的名称和类型、在编辑器中显示的模型等内容。它们通常在单独的文件中指定，你可以将该文件[加载到编辑器中](#entity_definition_setup)。

### Mod {#mods}

Mod（游戏模组，game modification 的缩写）是一种通过自定义玩法和资产来扩展基于 Quake 引擎游戏的方式。自定义资产包括模型、音效和材质。从游戏的角度来看，Mod 是游戏目录下的一个子目录，附加资产以独立松散文件或归档文件（如 pak 文件）的形式存放在其中。对 TrenchBroom 而言，Mod 只是提供资产，其中一些资产替换游戏中的现有资产，另一些则是全新的。例如，Mod 可能会为某个实体提供新模型，或者提供一个全新的实体。为了使这些新实体能在 TrenchBroom 中使用，需要两样东西：首先，TrenchBroom 需要这些实体的实体定义；其次，TrenchBroom 需要知道应从哪里寻找要在视图中显示的模型。第一个问题可以通过让 TrenchBroom 指向备用[实体定义文件](#entity_definitions)来解决，第二个问题可以通过为当前地图[添加 Mod 目录](#mod_setup)来解决。

每个游戏都有一个默认 Mod，TrenchBroom 始终会加载它。例如，Quake 的默认 Mod 是 _id1_，即包含所有游戏内容的目录。TrenchBroom 支持多个 Mod；在使用多个 Mod 的情况下，必须有解决资源同名冲突的策略。例如，Mod 可能会为默认 Mod 中定义的实体提供实体模型，以便用更精细的模型替换默认模型。为此，Mod 会提供一个与要替换的模型同名的实体模型。为了解决此类同名冲突，TrenchBroom 为 Mod 分配了优先级；如果不同 Mod 之间发生名称冲突，优先级最高的 Mod 获胜。请注意，默认 Mod 的优先级始终最低。

### 材质与材质集合 {#materials}

材质定义了表面如何渲染以及如何与光线相互作用。在 TrenchBroom 中，材质通常与纹理密切相关。当 TrenchBroom 在文件系统中找到纹理时，会自动为其创建默认材质。对于 Quake 3，其他材质属性从着色器（shader）文件中读取。材质通常不是单独提供的，而是作为材质集合提供。材质集合可以是一个包含独立图像文件的目录，也可以是一个归档文件（如 wad 文件）。某些游戏（如 Quake 2）自带可直接被 TrenchBroom 加载的纹理，此类纹理称为_内部（internal）_纹理。另一方面，_外部（external）_纹理是你通过加载 wad 文件提供的纹理。由于某些游戏（如 Quake）没有直接自带可用的纹理，你必须获取想要使用的纹理并通过[加载 wad 文件](#material_management)将其手动添加到 TrenchBroom 中。

多个材质集合可能包含同名材质，从而导致名称冲突。这种冲突通过查看材质集合的加载顺序来解决——最近加载的材质在冲突中获胜。除非使用 wad 文件，否则你无法控制加载顺序。

## 启动 {#startup}

TrenchBroom 启动时首先显示的是欢迎窗口。该窗口允许你打开最近编辑过的地图、创建新地图，或在计算机中浏览并打开现有的地图文件。

![TrenchBroom 欢迎窗口](images/WelcomeWindow.png)

你可以点击标有“New map...”的按钮创建新地图，也可以点击标有“Browse...”的按钮在计算机中查找地图文件。双击窗口右侧列表中的某个文档即可将其打开。左侧的浅灰色文本显示了当前运行的 TrenchBroom 版本信息。如果你希望向官方报告编辑器的问题，版本信息将非常有用（详见[此处](#reporting_bugs)）。

如果选择创建新地图，TrenchBroom 需要知道该地图适用于哪款游戏，并会显示一个对话框供你选择游戏以及适用的地图格式。当你打开现有地图时，也可能会显示此对话框。TrenchBroom 会尝试从地图文件中检测这些信息，但如果检测失败，则需要手动选择游戏和地图格式。

![游戏选择对话框（Mac OS X）](images/GameSelectionDialog.png)

对话框右侧显示支持的游戏列表。游戏列表下方是用于选择地图格式的下拉菜单；只有游戏支持多个地图格式时才会显示。Quake 就是一个例子，它同时支持标准格式和 Valve 220 地图格式。上面的截图中，列表里的游戏实际上都没有在硬盘上找到，因为相应的游戏路径尚未配置。TrenchBroom 允许你为缺失的游戏创建地图，但编辑器不会显示实体模型，材质等其他资源也可能缺失。点击“Open preferences...”按钮可以打开游戏配置偏好设置。点击[这里](#game_configuration)了解如何配置支持的游戏。

选择游戏和地图格式后，TrenchBroom 会打开带有新地图的主编辑窗口。下一节将概览该窗口及其主要元素。如果想了解如何[使用 Mod](#mods)或[添加材质](#material_management)，可以直接跳到相应章节。

## 主窗口 {#main_window}

主窗口由菜单栏、工具栏、编辑区域、右侧检查器和底部信息面板组成。下面的截图包含三个编辑区域：一个 3D 视图和两个正交 2D 编辑视图。

![主编辑窗口](images/MainWindow.png)

用鼠标拖动分隔线可以改变编辑区域、检查器和信息栏的大小，检查器中的部分分隔线也同样如此。厚度为 2 像素的分隔线可以拖动。关闭窗口时，分隔线位置和编辑窗口大小会被保存。下面的小节将介绍主窗口最重要的部分：编辑区域、检查器和信息栏。工具栏和菜单将在后续章节中详细说明。

### 编辑区域 {#the-editing-area}

编辑区域分为两部分：顶部的上下文相关信息栏和下方的视图。信息栏中的控件取决于当前激活的工具。你可以通过工具栏按钮、菜单或相应快捷键切换旋转工具、顶点工具等工具。上下文控件用于执行与当前工具相关的操作，例如在旋转工具中设置旋转中心，或在默认移动工具中按指定增量移动对象。此外，信息栏右侧有一个名为“View Options”的按钮。点击该按钮会展开下拉菜单，其中包含用于[过滤](#filtering_rendering_options)视图中的对象，或改变视图[渲染内容](#filtering_rendering_options)的控件。

![带有视图下拉菜单的信息栏（Windows 10）](images/ViewDropdown.png)

视图分为两种：3D 视图和 2D 视图。TrenchBroom 允许你控制视图布局，可以使用一个、两个、三个或四个视图。参阅[视图布局与渲染](#view_layout_and_rendering)了解如何改变视图布局。当视图少于四个时，可以按 #action(Controls/Map view/Cycle map view)循环切换其中一个视图。可循环的视图及其顺序如下表所示：

视图数量            循环视图              循环顺序
----------------    ------------         -------------
1                   单一视图              3D > XY > XZ > YZ
2                   右侧视图              XY > XZ > YZ
3                   右下视图              XZ > YZ
4                   无

2D 视图有三种：XY、XZ 和 YZ。也可以分别将它们理解为顶视图、前视图和侧视图。下表总结了三种 2D 视图的属性。请注意，基于 Quake 的引擎使用右手坐标系。

视图        右轴         上轴       法线轴        名称
--------    ----------    -------    -----------    ----
XY          +X            +Y         +Z             顶视图
XZ          +X            +Z         -Y             前视图
YZ          +Y            +Z         +X             侧视图

法线轴是从相应 2D 视图观察时垂直于屏幕的轴。对于 XY 视图，法线轴是正 Z 轴；对于 XZ 视图，法线轴是负 Y 轴。从数学角度看，法线轴是右轴与上轴的叉积。有时我们也把反向法线轴称为深度轴，因此 XY 视图的深度轴是负 Z 轴。由前两个轴张成的平面称为 2D 视图的视平面，所以 XZ 视图的视平面就是 X/Z 平面。

![罗盘](images/Compass3D.png) 每个视图的左下角都有一个罗盘，指示该视图的摄像机朝向。在 3D 视图中，旋转摄像机时可以看到罗盘随之旋转。在 2D 视图中，罗盘轴线是固定的，但它们指明了该视图坐标系中的右轴和上轴。罗盘指针的颜色代表轴向：红色代表 X 轴，绿色代表 Y 轴，蓝色代表 Z 轴（对应 RGB 与 XYZ）。

最多只能有一个视图获得焦点，也就是说只有它能接收鼠标和键盘事件。视图边框上的高亮矩形表示焦点。如果没有视图获得焦点，需要点击其中一个来激活它。视图获得焦点后，焦点会跟随鼠标指针；要将焦点移到另一个视图，只需将鼠标移过去。也可以从菜单中选择 #menu(Menu/View/Maximize Current View)最大化当前视图。再次按下相同快捷键即可恢复之前的视图布局。

### 地图边界 {#map_bounds}

![McKinley Base 与 Quake 地图边界](images/CTF1Bounds.png)

游戏引擎通常会限制可使用或可游玩的空间范围。TrenchBroom 可以显示这一限制，作为创建地图时的参考。这些边界会在 2D 视图中显示为橙色正方形或矩形。例如，上图显示了 Quake 地图 McKinley Base（Threewave CTF 中的 ctf1）处于 Quake 地图的标准边界内。

![地图属性（Ubuntu Linux）](images/SoftBounds.png) 如果为游戏配置了边界，它们通常表示特定游戏引擎的最后一个官方版本或补丁所遵循的限制。这些边界可能不符合你的具体情况，因此你可以通过场景工具栏或视图菜单中的**地图设置…**（#key(Ctrl)#key(1)）禁用或修改显示的边界。

在 Quake 引擎游戏中，这些边界限制了可容纳玩家、物品或其他实体的空间范围。静态几何体（普通 Brush）可以延伸到更远的位置，因此这些限制通常称为“软边界”。不过对 TrenchBroom 来说，它只是按照[游戏配置文件](#game_configuration_files)中指定的坐标绘制橙色线条……如果目标不是 Quake 引擎游戏，边界也可能代表其他含义。

无论如何，请记住显示的边界只是参考，用于帮助你将地图保持在目标游戏引擎的限制之内。在 TrenchBroom 中修改边界不会改变游戏中的实际行为！

### 检查器 {#the-inspector}

检查器位于主窗口右侧，分布在多个页面中的各种控件用于修改当前选中对象的属性。选择 #menu(Menu/View/Toggle Inspector)可以显示或隐藏检查器。按 #key(Ctrl)#key(1) 打开**地图设置…**，按 #key(Ctrl)#key(2) 打开场景与属性，按 #key(Ctrl)#key(3) 打开面检查器。

![Outliner、实体与面检查器](images/Inspector.png)

**场景**页统一管理[图层](#layers)、对象层级和实体[属性](#entity_properties)。底部内容浏览器的“实体”文件夹用于[创建点实体](#creating_entities)和[设置实体定义](#entity_definitions)。**地图设置…**包含[地图边界](#map_bounds)与 [Mod](#mods)。面检查器保留图形化 [UV 编辑器](#uv_editor)、面属性和[材质浏览器](#material_browser)。

### 信息栏 {#the-info-bar}

选择 #menu(Menu/View/Toggle Info Panel)可以显示或隐藏信息栏。信息栏包含 TrenchBroom 输出消息、警告和错误的控制台，以及用于查看、过滤和解决地图问题的实时[问题浏览器](#issue_browser)。

## 摄像机导航 {#camera_navigation}

TrenchBroom 中的导航非常简单直观。你主要使用鼠标移动、平移和环顾摄像机，也可以使用一些快捷键更精确地定位摄像机。和 Quake 一样，摄像机不能翻滚；换句话说，上方始终是正 Z 方向，下方始终是负 Z 方向。摄像机行为可以在[偏好设置](#mouse_input)中控制。

### 环顾与移动 {#looking-and-moving-around}

在 3D 视图中，按住鼠标右键并拖动即可环顾四周。移动摄像机有多种方式。最直接的方法是滚动鼠标滚轮，沿观察方向前后移动摄像机。如果希望滚轮沿鼠标指针所指方向移动摄像机，可在偏好设置中勾选“Move camera towards cursor”。要横向或上下移动摄像机，按住鼠标中键并向任意方向拖动。平板用户可以在偏好设置中启用通过按住 #key(Alt)水平移动摄像机的选项。此外，还可以使用以下快捷键：

方向         按键
---------    ---
前进         #action(Controls/Camera/Move forward)
后退         #action(Controls/Camera/Move backward)
左           #action(Controls/Camera/Move left)
右           #action(Controls/Camera/Move right)
上           #action(Controls/Camera/Move up)
下           #action(Controls/Camera/Move down)

要调整这些快捷键的移动速度，可以前往[偏好设置](#mouse_input)调整相应滑块，或在 3D 视图中按住鼠标右键并滚动滚轮。

### 环绕 {#orbiting}

摄像机环绕模式允许你围绕一个可选点旋转摄像机。可以这样理解：点击一个 Brush，在地图中定义一个点，该点就是摄像机的环绕中心。想象一个以刚才点击的点为球心、摄像机与该点距离为半径的球体。环绕时，摄像机会沿球面移动，同时调整方向，使其始终朝向同一个点。从视觉上看，这相当于围绕环绕中心旋转整张地图。当然，实际旋转的只有摄像机的位置和方向。由于上下方向始终固定，摄像机不能越过环绕球体的南北极。

编辑 Brush 时，摄像机环绕模式非常有用，因为它可以快速从各个方向查看 Brush。建议亲自尝试以体会其便利性。按住 #key(Alt)并用鼠标右键点击拖动即可进入环绕模式。环绕中心是最初点击的地图位置。左右拖动会使摄像机水平环绕，上下拖动会使摄像机垂直环绕。环绕过程中可以使用滚轮改变环绕半径。

### 自动导航 {#automatic-navigation}

从菜单中选择 #menu(Menu/View/Camera/Focus on Selection)可以将摄像机置于当前选择的中心，使所有选中对象可见。摄像机不会旋转，只会改变位置。请注意，该操作也会调整 2D 视图，使选择内容在其中可见。

最后，你可以将摄像机移动到指定位置。选择 #menu(Menu/View/Camera/Move Camera to...)，然后在弹出的对话框中输入位置即可。这不会影响 2D 视图。

## 浏览 2D 视图 {#navigating-the-2d-viewports}

![链接的 YZ 和 XZ 视图](images/Linked2DViewports.gif)

浏览 2D 视图自然比浏览 3D 视图简单得多。按住鼠标中键或右键并拖动即可平移视图，滚动滚轮可以调整缩放。如果视图布局显示多个 2D 视图，这些视图会相互链接。具体来说，缩放系数会同步，因此所有 2D 视图始终保持一致的缩放级别；视图也会沿相同的轴同时平移。这意味着沿 X 轴平移 XY 视图时，XZ 视图也会沿 X 轴平移，无需手动平移两个视图。此外，缩放始终保持鼠标指针下的坐标不变，因此将鼠标悬停在目标对象或区域上并缩放即可聚焦该位置。

## FOV 与缩放 {#fov-and-zoom}

对于 3D 视图，可以在[视图偏好设置](#view_layout_and_rendering)中拖动滑块调整摄像机 FOV（视野）。该设置会永久保存。

要临时调整摄像机缩放，按住 #key(Shift)并滚动鼠标滚轮。按 #action(Controls/Map view/Reset camera zoom)可重置缩放系数。
